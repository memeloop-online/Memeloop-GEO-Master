# 报告只读预览

本文件描述 W09/P14/P00 的临时报告预览，不修改冻结产品规格。实现与验证进度以 `WORKLOG.md` 为准；它不是正式周报、独立 AI 测量或下一轮优化的替代品。

## 用户路径

P14 报告列表展示当前周期的“临时预览 · 未保存为正式周报”，与已保存报告分开。没有正式报告时仍可以预览；用户可以刷新，页面不以持续轮询触发业务任务。P00 可调用独立的 `report_preview` 工具；原 `report_get` 读取正式快照，`report_reduce` 生成到期正式快照，三者语义不混用。

预览显示完整计划分母、文档/发布/测量覆盖、缺口、归纳与证据。缺测不算未提及，未知发布不算失败，暂缺清单不显示为零。来源未保存封存或状态迁移时间时，继续标明时间依据不足，不能将当前状态冒充已证明的历史状态。

预览中的证据直接来自同次响应，不使用虚构报告 ID 请求正式报告证据，也不提供未标注的正式报告 CSV。已保存报告的详情、版本和 CSV 路径不受影响。

## 时间和数据契约

- `GET /api/v1/cycles/{id}/report-preview?project_id=<uuid>`：沿用会话与项目只读权限，响应 `Cache-Control: no-store`。请求不接受调用方指定证据时间、报告输入或成功测量数据。
- `ReportPreview` 使用现有报告的覆盖、分组、结论及证据类型；去掉 `report_id`、`revision`、`correction_of`，增加固定 `kind: "preview"`。覆盖 `status` 表示数据完整程度，不表示已保存或正式交付。
- `generated_at` 是本次请求的服务器时间，`cutoff_at` 是原周期冻结截止；`evidence_as_of = min(generated_at, cutoff_at)`。三种时间在界面分开显示。
- 原报告窗口、清单版本和已冻结计划分母保持不变，不按已经过去的时间缩小测量分母。证据读取和校验使用同一截断时间，未来样本仍保留待完成状态。
- 截止后的预览也不吸收晚到证据，不生成更正版本。正式更正仍使用原有显式父快照及不可变版本机制。
- `input_hash` 是规范化输入内容的摘要，不是预览存档 ID。预览结论使用独立命名空间，不复用正式报告身份。

## 实现边界

领域的 `preview_report` 与正式 `reduce_report` 共享纯投影。正式报告的稳定 ID、修订规则、截止约束及更正语义保持不变。

API 的 `preview_cycle_report` 仅装配作用域内权威仓储读取，不调用正式报告保存、重放恢复、后继周期排期、资料物化、发布、查询执行或任务领取。正式分发清单优先于旧渠道发布计划，独立测量计划仍保留。

P00 的 `report.preview.v1` 只接受可选 `cycle_id`；省略时由 Rust 解析当前项目周期，不能由脚本选择租户、项目或时间。它沿用工具调用记录，并在记为成功前校验返回项目、周期及时间边界。工具调用记录不等于写入正式报告。

本批宿主面为 `geo.hostops.v9`，共 26 项能力；部署须同步 Rust 和重新生成的 MemeLoop bundle/摘要。

## 验证范围

必须覆盖：

1. 截止前不完整预览可读，而正式生成仍受截止约束。
2. 截止后证据时间截断，晚到观察不被偷纳入。
3. 重复预览不增加正式报告，不推进当前周期。
4. 冻结分母保留所有目标；缺测、未提及、未知和时间依据缺口保持区别。
5. 跨项目/租户读取失败，P00 拒绝返回其他项目或周期的结果。
6. P14 空正式列表、刷新、加载、错误、无当前周期和已保存报告路径不相互混淆。

生产多副本下跨仓储读取不构成数据库级统一快照。预览是临时读视图，不能拿它替代正式报告的不可变重放或据此结算费用。真实外部账号发布、独立官方搜索及商业/容量验收仍需分别完成。
