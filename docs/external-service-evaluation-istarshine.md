# 外部服务评估：GEO 洞察（geo.istarshine.com）

更新时间：2026-09-30  
评估方式：公开首页与登录页只读检查；未提交验证码，未进入账号内页，未创建、发布或修改任何数据。

## 已验证的公开能力

首页明确展示了以下产品能力：

- AI 可见度追踪：品牌在各大模型中的提及频率、情感倾向、排名和竞品对比；
- AI 推荐排名榜和 AI 可见度排行榜；
- 引用频次与分布、高影响力媒体识别、AI 内容偏好解析；
- AI 友好内容评分、结构化数据生成、引用源优化；
- 公共榜单文案声称统计 DeepSeek、豆包、腾讯元宝、通义千问、文心一言等国内模型。

这些内容证明它至少把“模型回答采样/抽取”和“品牌、引用、排名聚合”作为产品概念，但公开页面没有证明其使用了哪些官方 API、哪些网页/客户端观测面，也没有证明发布器、账号池、出口 IP、重试或回执模型。

登录页使用手机号、密码和图形验证码。由于验证码需要人类识别，当前没有进入账号内页，因此下列项目不能据此服务验证：

- AI 供应商的实际接入协议、模型/搜索开关和计费；
- 问题集、抽样次数、答案及引用的原始保存；
- 文章生成、预览、发布、更新、查回和失败恢复；
- 账号接入、代理/IP 配置、批量发布和吞吐能力。

## 对 Memeloop GEO 的直接增量要求

### 1. 供应商能力必须拆成模型与搜索两层

为每个 AI 供应商保存能力快照，而不是只保存一个“已接入”标志：

- `chat_completion`：普通对话；
- `web_search`/`deep_research`：官方搜索或联网模式；
- `citations`：引用 URL、标题、片段和供应商 request/message ID；
- `structured_output`、`streaming`、`image_input` 等附加能力；
- 模型、区域、观测面、协议版本、价格和最近探测时间。

普通聊天成功不能推断官方搜索可用。固定测量协议必须绑定 `provider + model + search_mode + surface + market + language`，发生降级时记录为代理观测或缺测，不能伪装成同一渠道。

### 2. 搜索接入采用官方 API 优先、消费端网页其次

每个测量连接器分为两种明确模式：

1. `official_api`：使用供应商公开 API 的联网/搜索参数，保存请求、响应、引用和用量；
2. `consumer_surface`：无头 Chromium 或移动 Runner 操作实际用户界面，保存页面、可见模型、搜索开关、答案、引用和截图。

两种模式不得合并分母。API 结果只能标记为代理观测，不能宣称等同于消费者端答案。网页模式必须固定浏览器版本、地区、语言、出口租约和连接器版本。

### 3. 发布器要复用“目标资源 + 执行环境 + 证据”模型

无论 API、网页、云手机还是 CMS，都统一成：

- `PlatformTarget`：平台能力、内容类型、发布/更新/查回能力；
- `AccountBinding`：登录态、账号、租户归属和凭据引用；
- `ExecutionProfile`：浏览器/设备、出口 IP 或 IP 池、限速、并发和地区；
- `PublicationIntent` / `Attempt` / `Receipt`：稳定幂等键、尝试、外部 ID、公开读回证据、未知结果。

文章发布至少要支持草稿生成、渠道变体、发布、更新、公开验证、失败分类、结果未知查回和不重复发布。当前不能从公开页面确认该服务是否具备这些能力，不能把它作为我们的实现依据。

### 4. 增加供应商连接器探针和黄金样本

W04/W09 的验收应增加：

- 能力探针：分别探测普通模型、官方搜索、引用、流式和结构化输出；
- 黄金问题集：固定问题、品牌集合、区域、语言和采样序号；
- 原始证据：答案、引用、截图/响应、供应商 request ID、用量和错误；
- 降级矩阵：官方 API、官方搜索 API、消费端网页、移动端各自独立统计；
- 连接器版本与回归对比：供应商页面或 API 变化导致解析失败时进入缺测，不自动改口径。

## 对计划的结论

这项外部服务适合作为竞品参考，补充了“排行榜、内容评分、引用源优化”的产品表达；它没有提供足够公开证据证明其技术方案，因此不引入其代码、数据模型或未经验证的供应商接法。

我们的核心差异保持不变：企业资料第一次 fan-out 为可追溯知识文档，第二次 fan-out 到全部适用发布平台，再用独立 AI 渠道测量和发布证据 reduce。新增的供应商能力快照、API/消费端观测分层和发布证据要求，服务于这个闭环。
