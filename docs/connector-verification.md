# 连接器验证接线契约

本文细化既有产品规格，不改变冻结需求。当前注册表底层已实现；下述生产投影、格式映射和恢复扫描仍待实现，不能据此声称真实渠道已验证。

## 不循环依赖的执行路径

正常源资料发布 → 保存发送尝试及公开读回 → Rust 投影验证记录 → 自动取得对应格式能力 → 后续正文分发。

不新增测试文章、发布审批或让运营者手工标记验证。账号登录、runner 健康、版本发现和界面开关均不是发布证明。没有配置记录时允许已有源资料发布路径执行；明确停用后必须阻止新的源资料及生成内容发送，测量保持独立。

## 可信生产入口

内部服务只接收作用域、目标 ID 和尝试 ID：

```text
project_saved_publication_verification(scope, target_id, attempt_id)
```

不接收调用者自报的结果、账号、版本、格式、URL 或验证标志。重新读取已保存的目标与尝试，验证：

- 运营商、租户、项目、目标和账号关联一致。
- 结果为实际公开读回 `Verified`，具有明确 live provenance，非 fixture。
- 冻结标题、正文、payload hash 与读回哈希一致；平台 URL、账号所有权与原始证据有效。
- `claimed_at <= occurred_at <= received_at`；不能用接收时间补造缺失的观测时间。
- 保存原始账号、平台、位置、source/version 或正文 revision/variant/intent、payload hash、连接器版本及事件时间引用，不能替换成当前可变数据。

已有组合式 `Verified` 结果可以同时包含发送回执与实际读回；不得伪造额外的 `Published` 事件。现有注册表的纯 DTO 校验不能代替以上持久来源核验。

同一尝试与格式使用确定 ID 或唯一键；同值重放复用，异值冲突。优先原子保存结果与投影，或在结果保存后投影并扫描已完成但未投影的尝试。投影失败不重新发送外部文章。

## 版本与 provenance

版本标识实际部署代码，不是验证结论。生产 runner 从加载的 adapter 元数据盖章版本和 provenance，不能信任 adapter 返回值覆盖。注入的测试 adapter 只能产生 fixture；HTTP 请求不得选择 provenance。

在以上来源约束成立后，源代码推导实现也可凭真实成功读回取得能力；不能仅因版本名字含 `unverified` 或 `source_derived` 永久拒绝它，也不能通过改名冒充成功。保留旧 fixture 版本防御，真实版本变化需新的匹配证据。发现接口只报告部署信息。

## 内容类型与线上格式

文档语义类型和发布线格式分离。普通源资料正文没有 `faq` 等语义标识，不能凭任意文章成功就自报这些类型均已验证。

为实际 `{title, body}` 序列化定义 Rust 拥有的格式键，例如 `plain_text_article.v1`。验证记录认证这一线上格式；分发保留原文档类型，并通过明确映射判断是否使用相同序列化。富媒体、富文本等格式需独立证据，不自动继承纯文本能力。

第一次有效投影仅在设置缺省时创建自动启用的默认配置；已经存在的显式停用、内容范围及修订不被覆盖。发送前重新检查实际格式、部署版本和当前配置。既有冻结清单不因设置变化被静默重写，后续清单版本继续遵循意图复用和未知结果不重发。

## 实现落点与测试

- runner：执行结果盖章 provenance 和部署版本。
- domain：验证来源引用、线上格式与语义映射、幂等投影契约。
- persistence：持久尝试来源核验、唯一投影、缺省自动配置与恢复扫描。
- API：结果保存后的投影触发、生产装配、发送前复核。
- UI：展示连接、部署、实测和启用状态；不提供自报验证按钮。

必须覆盖：无配置的首次真实源资料结果、重启补投影、重复/并发幂等、跨作用域拒绝、正文/账号/URL/版本不符、fixture/未知/仅登录不提升、明确停用不被覆盖、版本升级停止新发送、富媒体不继承纯文本证明，以及历史清单不变。合成契约测试不代替真实外部验收。
