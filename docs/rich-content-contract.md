# 生成内容富文本实施契约

状态：文本、列表、代码、表格及版本导出已通过本地整合；媒体与富文本发布尚未完成。实际测试和提交后 CI 状态见 `WORKLOG.md`，不能据此认定整项交付。产品范围仍以 `product-plan-v1.md` 第 8 节为准。知识资料 Markdown 编辑与生成内容的结构化正文属于不同保存路径，前者完成不能代替后者。

## 保存与兼容

保留 `StructuredDocument { title, blocks }` 和每个顶层块的 `block_id`、`citation_ids`。新增可选 `schema_version: 2`，缺省为旧版且序列化时不输出新增字段。旧正文仅打开、预览或读取不得自动升级。

新增 `kind: rich` 及可选 `rich: { version: 1, node }`，内部采用与启用的 Tiptap/ProseMirror 扩展一致的强类型节点树。富文本块的旧 `text/items` 为空，不再维护会与节点树分歧的第二份正文。新版本可混合旧块和富文本块；未知节点、标记、属性或不合法组合必须明确拒绝，不能退回纯文本保存。

支持范围：

- 段落、1—6 级标题、换行、加粗、斜体、删除线、下划线、行内代码及安全链接。
- 有序/无序及嵌套列表，有序列表起始序号。
- 代码块及语言属性，代码文本不参与 Markdown 转义。
- 表格、行、表头和单元格；校验实际启用的对齐、合并属性及行列关系。
- 媒体引用：不可变对象版本、摘要、替代文本和说明；不是任意外部 `src`。

节点数、深度、文本量和表格大小沿用有明确错误的输入校验，不增加人工审批或发布放行步骤。编辑器仅启用保存、读回和导出都支持的能力。

## 导出与已有发布

旧 `StructuredDocument::markdown()` 的字节行为保持不变。分发、发送前校验及跨周期复用会重新计算正文，并与已冻结的变体/摘要比较；不能通过全局改变转义方式破坏旧资产。

新 schema 使用独立版本的 HTML/Markdown 渲染器。复杂表格在 Markdown 中保留可表达语义的 HTML，不丢单元格结构。导出绑定不可变内容版本；不得重新渲染并覆盖已保存的历史导出或发布载荷。

新增 schema 的生成、检查和变体策略使用新版本标识，不替换已有冻结描述符。`plain_text_article.v1` 不自动获得富文本和媒体发布能力；不支持完整内容的渠道保留覆盖项和明确原因，不扁平化后声称已发布原内容。

## 来源、检查与自动修复

证据仍绑定顶层块；表格或列表内文本共享该块的受限证据集合，原有精确原文引用、来源版本与定位不变。拆块保留可追溯关系并为新增块分配新 ID；合块只继承原有合法证据。粘贴 HTML 不能导入可信证据 ID。

自动检查读取所有富文本、表格、代码、媒体说明和替代文本。标题及每个顶层块均必须有检查结果；不能因结构变复杂而漏检。

旧模型修复仍接受 heading/paragraph/list；新正文使用 `rich-content-check-v2`、`rich-content-repair-v2` 的租约与模型契约，领取和完成时都匹配版本。禁止把富文本传给旧修复器，再将退化的纯文本当作成功修复。未指出的块保持原样；指出的块可以更正文本、删除无依据子树或整块，幸存节点保持原有结构、属性和标记，不引入新块或证据身份。手动编辑、修复和复用分支均生成新版本并失效旧检查，不改写已发布版本。

版本导出接口为 `GET /projects/{project_id}/contents/{asset_id}/revisions/{revision_id}/export?format=markdown|html`。返回 `{ revision_id, format, media_type, filename, content }`；Markdown 使用该不可变版本保存的原始导出字节，HTML 使用对应 schema 的转义渲染。接口只读，按租户、项目、资产和版本校验；存在未解析媒体时明确失败。

## 媒体边界

复用已有受作用域约束的存储对象标识，不另建无版本公开 URL 列表。附件存在不代表允许公开发布：

1. 服务端核验租户/项目、对象提交状态、版本和摘要。
2. 核验实际媒体类型及公开使用资格；没有可证明的公开用途绑定时，建立专用绑定和查询接口。
3. 预览通过授权读取；导出打包授权媒体为相对文件，无法解析时返回明确失败。
4. 普通编辑、复用分支、自动修复、导出及分发共用边界。持久写入事务中复核资格，覆盖并发撤销。

现有普通编辑 HTTP 路径直接调用 repository，不能只在另一条 service 路径增加检查后声称所有入口已覆盖。

## 实施分工

- 领域：`crates/domain/src/content.rs`、独立富文本模块、分发兼容校验及旧版黄金测试。
- API/持久化：正文保存、复用分支、模型检查/修复、版本化导出和媒体资格。正文 JSONB 本身不需要迁移；新增媒体用途绑定按实际表结构独立迁移。
- 前端：`StructuredContentEditor.tsx`、内容 API 类型和详情页，复用 Tiptap 扩展；保留一秒防抖保存、冲突草稿和版本证据。不得使用递归取纯文本作为保存降级。
- 交付：实际浏览器编辑/刷新/导出、独立 PostgreSQL 读回和现有分发复用回归。知识资料编辑器不在本任务改动范围。

## 必需验证

- 旧版反序列化/序列化、Markdown、冻结变体 ID/摘要、检查和复用关系不变。
- 新版每种节点、标记与属性经编辑、API、PostgreSQL、重新加载、HTML/Markdown 导出完整保留。
- 非法节点/链接/表格/媒体、过深输入和跨项目对象明确失败，没有静默扁平化。
- 检查覆盖所有文本；修复不降级 schema、不丢失未受影响结构和证据。
- 新编辑与复用分支不覆盖来源版本和历史检查。
- 媒体并发撤销在全部写入与发送入口生效。
- 浏览器覆盖粘贴、嵌套列表、表格、撤销/重做、自动保存、冲突保留和导出；不支持的发布渠道显示真实原因。
