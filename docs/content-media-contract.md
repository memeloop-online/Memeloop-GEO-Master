# 内容媒体接入契约

状态：绑定、静态图片检测与编辑器接入已通过本地整合，待提交后 CI；尚未作为完整媒体能力交付，ZIP 导出和媒体发布适配待实现。产品范围见冻结规格第 8 节，正文格式见 `rich-content-contract.md`。

已具备的底层接缝：`KnowledgeRepository::get_attachment_object_bytes` 返回同项目已提交 Agent 附件的原始字节快照，核对版本、摘要和长度；内存/数据库实现及重连、隔离、损坏回归已接入。它本身不是公开 API、类型检测、媒体用途绑定或发送授权。绑定仓储、API 与前端的实际验证状态以 `WORKLOG.md` 为准。

## 用户流程

编辑器复用现有附件上传接口。上传图片或选择已有附件后，自动创建当前项目的媒体用途绑定，成功后插入不可变媒体引用；不增加审批、声明或确认步骤。失败时保留普通附件并说明原因，不插入无法保存的图片。媒体选择器只列出当前项目可使用的对象。

初期支持 PNG、JPEG、WebP 静态图片。服务端根据真实字节判断格式、核对摘要和长度、读取尺寸并完整解码验证；限制解码资源，不因扩展名或声明 MIME 放行 SVG、HTML、损坏或超大图片。使用维护中的解码库，添加前确认版本、功能开关与传递许可证。

当前采用精确版本 `image 0.25.10`、`png 0.18.1`、`zune-jpeg 0.5.15`；PNG 检查读入的动画元数据并完成尾部读取，JPEG 使用严格解码及结尾标记策略，WebP 核对 RIFF 长度并拒绝动画。完整像素解码不等于证明所有可选容器段均规范，尤其 JPEG/WebP 不宣称规范化校验；原始字节保持不变。解码在阻塞线程执行，并同时限制编码大小、尺寸、像素数和解码内存。

## 数据与接口

媒体引用沿用 `object_id`、`object_version`、`sha256`、`alt`、`caption`，不允许任意外部 URL 替代对象身份。

新增项目作用域 `content_media_bindings`：运营商、租户、项目、对象三元组、绑定 ID、真实媒体类型、长度、尺寸、active/withdrawn 状态与时间。相同作用域/对象三元组唯一；撤销为终态，普通请求重试不能重新启用历史引用。重新上传取得新对象后才能建立新绑定。

接口前缀 `/projects/{project_id}/content-media`：

- `POST /bindings`：写权限核验、验证已提交对象字节，幂等建立用途绑定。
- `GET /bindings`：分页查询可用媒体。
- `GET /bindings/{id}/bytes`：鉴权读取预览；真实 Content-Type、nosniff，最终响应由统一中间件设为 `Cache-Control: no-store`，禁止共享和私有缓存保存。
- `DELETE /bindings/{id}`：撤销后续公开使用，不删除原附件。

预览经现有 API 客户端鉴权读取 Blob，卸载时释放 Blob URL，不将对象密钥或永久公共地址交给前端。现有附件 metadata 接口不等于字节读取能力。

## 写入和并发撤销

PostgreSQL 解析器接受调用方事务，不能独立查询后返回一个随时失效的布尔值。锁顺序统一为项目行、既有内容/分发锁、按对象身份排序的存储对象与绑定行、字节读取；绑定创建/撤销参与同一项目锁协议。

覆盖普通保存、copy-on-write、生成、修复、重新就绪、交接与复用。`prepare_or_reuse` 是独立事务，包含已有就绪结果的提前返回，不能只改 `mutate`。只校验本次提交或复用的版本，不能因历史版本的媒体已撤销而阻止用户保存删除该图片的新版本。

内存仓储注入同一媒体协调器；内容提交取得媒体读 guard，创建/撤销绑定取得媒体写 guard，覆盖核验到提交。既有入口的顺序保持为项目 guard → 知识 guard（需要时）→ 媒体 guard → 内容状态锁。媒体 guard 只负责用途绑定竞争，不替代项目有效性和知识证据检查；不得在仓储内再次取得入口已经持有的项目或知识读锁。公平读写锁存在排队写者时，重复取得读锁也可能死锁。

绑定解析器从已持有的媒体 guard 读取，不能内部再次加锁。撤销不得在媒体写锁之后取得知识锁；需要原始字节的路径应先在正确作用域读取、验证不可变字节快照，再按上述顺序处理绑定。候选内容状态校验成功后原子替换，失败不能留下部分修改；仅检查新增版本或当前实际复用的版本，保留删除已撤销图片的正常编辑路径。直接仓储调用者也不能把媒体 guard 当作项目与知识校验已经完成的证明。

当前附件实现仅允许未提交上传写入字节，提交后应用接口不再修改对象或原始字节，但数据库并无不可变触发器。读取接口仍须核对作用域、对象版本、摘要、实际长度及提交状态；PostgreSQL 的媒体绑定解析继续使用调用方事务与行锁，不以进程内 guard 或元数据读取代替。

公开发送需要明确的线性化点：开始发送之前必须核验当前用途，已经开始的外部请求无法撤回。采用持锁发送或持久发送授权协议前，必须验证撤销竞争、超时和连接池占用；不得仅用早先的 preflight 查询声称竞态已解决。

## 导出和验证

保留现有无媒体 JSON 导出接口；新增版本级 `export-bundle?format=markdown|html` 返回 ZIP，包含文档和 `media/{object_id}-{version}` 相对文件。授权读取形成不可变字节快照后再打包；导出开始后的撤销无法召回已下载文件。未解析媒体明确失败，不伪造地址。

待实施的导出接缝：

- 内部批量快照返回已核验元数据和原始字节，不直接序列化。内存先读取全部不可变附件字节，再用同一个媒体读 guard 验证整批绑定及长度，释放后打包，避免知识/媒体锁倒置或递归加读锁。
- PostgreSQL 在一个作用域事务内取得项目、排序后的对象/绑定及字节锁；复用 `validate_bytes` 的实际读取结果，不能事务核验后再从另一连接取字节。事务提交后持有独立快照，不在压缩或下载期间占用事务。
- 撤销先完成则快照失败；快照授权先完成则允许该次导出完成。这是下载起点语义，不替代外部发送前授权。
- 从保存的结构化文档按对象完整身份解析相对路径，扩展名来自已核验 MIME。递归覆盖表格内媒体；不能对已有 Markdown 字符串做全局替换。重复对象去重，同对象/版本的摘要冲突拒绝。
- ZIP 使用成熟库与 Stored 模式，避免重复压缩图片；采纳具体版本前复核维护、安全和许可证。分配前检查整包媒体数量与总字节，阻塞线程负责打包，原图不重新编码。新增整包校验、撤销竞争、重连、精确字节和浏览器下载回归。

必需回归：真实类型与坏图、跨项目访问、同键重试/撤销终态、重新连接读回、保存/复用/导出/发送与撤销竞争、内存失败回滚、排队项目/知识写者下无重复加锁死锁、浏览器上传→插入→刷新→导出。富文本渠道尚未声明支持媒体时继续显示能力缺口，不能扁平化后冒充完整发布。
