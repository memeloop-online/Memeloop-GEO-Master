# AI 优先的交互整改

状态：用户明确提出的体验整改与实施待办，不代表下述能力已经完成。冻结产品规格保留；页面编号用于追踪能力覆盖，不要求每个编号成为一级导航。

## 首要原则

日常操作通过 AI 对话完成，包括导入、检索、编辑、配置、测量、发布和报告。专业页面用于查看同一份持久数据与手动微调，不是另一条必须走完的表单流程。每项页面功能必须对应可调用的真实业务工具，不能让 AI 只回复“请去某页操作”。

首次打开即显示输入框和上传入口，不要求点击“新建对话”。第一次发送文字或附件才创建持久会话。新项目可以先保存空草稿以建立数据隔离，但不得自动创建品牌资料、企业事实、优化周期或付费任务。用户切换历史会话不丢失未发送的草稿；重复发送和失败重试不得重复创建会话。

## 导航合并方案

以下为实施分组，合并的是入口和信息架构，不删除已有产品功能：

| 一级入口   | 归并内容与详情入口                                                                                                                |
| ---------- | --------------------------------------------------------------------------------------------------------------------------------- |
| AI 工作台  | 对话、附件、后台任务、业务结果卡片；项目总览作为详情而非必经流程                                                                  |
| 测量与洞察 | 第二位核心入口：从任意词或问题开始、问题预测与问题集、独立 AI 测量、原始回答/引用、采信信源、渠道建议、趋势与周报；不依赖企业资料 |
| 内容与发布 | 优化计划、动作/覆盖清单、内容资产、发布目标/状态和公开验证；编辑器从具体资料或内容版本进入                                        |
| 企业知识   | 来源列表、导入进度、来源/版本/证据、资料编辑、产品/事实；问答回到带知识上下文的 AI 对话                                           |
| 项目设置   | 品牌/目标、资源与账号组、连接器/出口、预算、成员及项目偏好；资料缺失不阻断独立测量                                                |

本分组按后续明确要求由六组合并为五组，替代早期六组导航实施结果。测量洞察是独立使用场景，不是发布流程的末端附属页。

## 从话题到渠道的核心闭环

### 首次价值与同页结论

默认测量入口直接开始了解产品、店铺或问题。完整问题使用已连接账号和实际可用的模型；用户可就地调整条件。仅有名称时，通过 AI 对话补齐影响提问的城市、品类或使用场景，并准备可查看的问题。首页示例填入可编辑草稿，首次发送才创建会话。

提交后在原页面持续展示进度和已取得的结果，依次回答：

1. 关注对象在本次哪些回答中得到推荐，附有效样本量和平台。
2. AI 怎样描述它，展示回答中的理由及可展开原文。
3. 同次还推荐了哪些具体对象，按实际推荐及明确排名展示。
4. 哪些内容值得优先补充、哪些来源值得研究，附本次引用文章和依据。

历史记录、问题集维护、传统搜索和详细条件作为次级入口；具体记录和报告链接仍可直接访问。阅读本次结论采用连续页面，用户按需展开证据。概览的数据范围固定到所选计划或报告，项目级历史信源单独标明范围。

自然推荐问题与点名了解问题分别组织。关注对象用于结果比较，发现性提问以实际购买或到店场景为中心。AI 回答中的描述与消费者真实口碑分别呈现；渠道机会说明引用依据和可采取的内容动作，效果通过后续复测观察。引用来源和发布能力分列。

验收记录用户主动输入、点击、页面切换、滚动及后台等待。已连接账号输入完整问题的目标路径为“输入 → 开始”两步，同页获得结果和下一步；名称含糊时通过一次必要澄清推进。实际操作数及剩余断点记录在工作日志。

用户只输入一个词即可开始。系统生成候选用户问题，标明是预测而非真实搜索量或真实用户提问；已有问题可直接测量。实际样本按供应商、模型、时间和观测面保存答案、引用和缺测原因。

信源洞察从实际引用聚合域名与具体文章，可回到原始样本核验；引用频次不能称为平台内部权重或整个市场的采信比例。根据样本范围推荐优先经营的渠道，并分别显示已接通发布、可接入和暂不支持直接发布。无发布连接器的渠道仍应提供可用洞察，不能从推荐中消失。

渠道建议与项目发布目标关联，支持 AI 按用户目标更新目标配置；不擅自创建账号或把推荐标成已发布。现有冻结任务保留原目标，后续任务采用新配置。用户可从信源、问题和结果直接回到带上下文的对话发起操作。

## OEM 与语言

应用壳、登录、空状态、错误和报告品牌取自统一部署/租户配置，不在页面散落品牌常量。OEM 应通过配置切换品牌名、标志、主题及默认语言，不复制前端代码。品牌配置不得把其他租户身份暴露给未登录访客。

界面文案进入统一国际化资源，覆盖导航、业务页、校验、状态、可访问性标签和日期/数字格式；不得仅翻译菜单便宣称国际化完成。用户资料和模型原始回答保留原语言。缺少翻译有可预测回退，不显示翻译键。公开仓库只保留通用品牌示例，不写真实客户配置。

不得保留指向 `demo-source`、`demo-content` 等不存在资源的一级入口。来源、内容、计划的详情只能由真实列表项或 AI 返回的真实资源链接进入。旧深链接保持兼容；活动高亮、浏览器前进后退与权限提示随新分组正确工作。

## 编辑器不得另造实现

- 企业知识与内容资产中的可编辑文本统一复用成熟开源所见即所得编辑器，优先评估 Tiptap/ProseMirror 等及所需扩展的许可、维护情况和 React 集成。
- 不再单列“内容编辑器”一级导航，也不自行实现 contenteditable 选区、撤销栈、表格模型或粘贴解析。
- 编辑必须写入真实版本；保留来源证据、原始文件与已发布版本。可编辑正文与不可修改的原件证据明确区分。
- AI 修改和用户手动修改共用版本/冲突处理；长文、表格、中文输入法、粘贴、撤销/重做、窄屏与键盘都需要验收。

## 登录与测量体验

- 远程登录优先使用成熟远程浏览器/桌面组件及配套服务，例如评估 noVNC/RFB 或同类现成方案；不把现有截图轮询继续扩成自制远程桌面。选型须覆盖中文输入、剪贴板、缩放、触屏、断线恢复和每账号会话隔离。
- 本机普通文字输入不默认掩码。默认界面不显示坐标、按键枚举、协议版本、模型内部标识等调试参数。
- 测量默认只需选择账号和输入问题，或选择已有问题集。企业资料只用于推荐，不是前置条件。
- 账号未连接、掉线和待验证应显示明确状态并提供就地连接/重连，不直接从列表消失。跨页面返回后自动刷新；问题集按当前项目读取，不能因没有优化周期而隐藏。
- 模型选项来自真实已登录网页；协议标识、计划键和时间由系统生成并持久化。无法读取时给出可重试原因，不要求用户查找内部 ID。
- 独立测量、发布计划和验证结果须区分，但共享结果页；不重复展示两套“开始测量”大表单。旧周期高级配置折叠或移入对应详情。
- 不新增人工审批、重复确认或人为放行。保留租户隔离、账号有效性、预算及真实证据校验等必要后端约束，但用可理解的状态呈现，不暴露实现细节。

## 持久性与验收

真实账号操作不得使用重启即清空的演示数据仓库。部署前验证应用与浏览器服务重启后：用户身份、账号加密会话、问题集、会话记录、测量计划和结果均可读回；密钥在仓库外持久保存。更新不得悄悄清空用户工作。

验收至少覆盖首次直接发送、附件-only、发送失败重试、历史切换、账号登录后跨页可见、任意问题/已有问题集测量、返回原始回答和引用、AI 发起与 UI 读回同一操作、手动微调版本、服务重启恢复。模拟夹具通过和按钮可点击不能代替真实完整流程验收。
