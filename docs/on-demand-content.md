# 按需内容生成

## 用户流程

在 AI 工作台提出主题、选择已有资料或上传资料，生成文章、对比指南或 FAQ。用户不需要先填写品牌、启动自动运营或建立周期。结果进入现有内容资产，支持检查、编辑、版本和下载；生成完成不自动分发。

按需资产生成已通过 PR #103 合并部署，PR #104 补齐对话文档条目发现；真实模型内容验收尚未完成。聊天回答与正式内容资产保持独立；不得用占位品牌、虚构预算或伪造周期绕过此差异。

## 实施边界

- 扩展现有内容执行来源为周期任务与按需任务，共用内容资产、修订、检查、修正及导出，不建立第二套正文模型或 Agent 循环。
- 按需请求包含项目内幂等键、主题、精确资料版本、文档条目及语言。每条目包含稳定 key、内容类型和可选标题／写作要求；市场与受众可选。
- 作用域由登录身份确定；冻结请求和资料版本，不在生成时改读当前聊天或全部公开资料。同键同输入返回原执行，不同输入返回冲突。
- 周期任务继续读取冻结周期配置；按需任务读取冻结请求。品牌缺省表示未指定，不将主题写作品牌。选证模型取得实际任务上下文，内部文档 key 只作标识。
- 保留现有分页分支、生成、检查、有限修正和持久执行。草稿项目可按需生成；暂停自动运营不等于禁止用户手动生成。
- 按需执行封存后完成；只有周期执行进入自动分发准备。后台扫描、事务内状态检查和运行时完成判定同时区分两类来源。

## 数据与接口

迁移 `0067` 将内容执行和文档清单的周期外键改为可空，显式记录任务来源，为按需任务提供项目外键和请求唯一约束，保留真实周期关联。既有执行数据在迁移中转换，运行时代码只读取最新格式。

`POST /projects/{id}/contents` 与 `content_create` Agent 工具调用同一服务，接受 UUID `request_id`。输入冻结、资料校验、幂等和调度由 Rust 承担，MJS 复用现有生成与检查流程；既有 `content_start` 仍表示周期内容启动。

对话通过 `content_execution_read` 查看进度，再通过 `content_items_read` 分页取得实际条目 ID，调用 `content_document_read` 读取正文；不从主题或文档 key 猜测条目 ID。分页复用已有 host op，不增加运行时能力编号。

跨包契约为 host v24／53 项：`ContentExecution.origin` 替代顶层 `cycle_id`，类型为 `cycle { cycle_id }` 或 `on_demand { request }`；执行引用携带 `handoff_id`，内容上下文的品牌允许为空。API、worker 和两份 bundle 必须配套更新并校验实际摘要。内容页通过现有项目资产接口读取结果，不以当前周期作为浏览条件。

## 验收

- 空草稿项目、无品牌、无当前周期，通过首页对话指定两份真实资料，生成文章与 FAQ 两项正式资产。
- 每项正文、引用和检查结果可读，编辑、下载、刷新与重启后版本一致。
- 多份可用资料存在时，只使用此次选定版本；撤销资料和跨项目版本不能进入新生成。
- 同键重试不重复生成；部分分支失败不丢失成功资产。
- 完成后没有新增自动分发目标或发布 outbox；只有用户另行要求分发才调用发布流程。
- 合成测试、真实模型生成和实际浏览器验收分别记录，不以受理或聊天回答替代资产生成完成。
