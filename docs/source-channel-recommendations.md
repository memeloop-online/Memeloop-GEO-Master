# 引用信源与发布渠道建议

状态：实施契约，尚未实现。沿用冻结产品规格和 `ux-consolidation.md`，不把引用域名统计视为已交付渠道推荐。

## 目标与证据

测量引用 → 信源归类 → 渠道能力与资源状态 → 项目目标修订 → 后续周期采用新目标。

无企业资料也能查看任意话题的信源。暂不能直接发布的渠道仍展示观察依据；引用不证明平台权威性、发布权限或发布后必然被引用。

复用 `citation_insights` 的真实搜索回执校验与分页读取。统计范围明确是当前返回的计划，不显示为全部历史、市场份额或搜索量。多个域名映射到同一渠道时，以 `(plan_id, target_id, attempt_id)` 去重引用回答，保留原样本回溯。

## 映射与能力

独立维护版本化 `SourceChannelRule`：规则 ID、允许的精确主机、可选路径约束、平台 ID、发布位置和宿主关系。子域名规则必须校验域名标签边界，不以子串匹配。

建议结果包含：

- 已识别渠道或尚未归类的信源；
- 映射规则版本、信源主机和当前页不同引用回答数；
- 证据范围与对应计划；
- 发布支持状态、具体缺失原因、是否已列入项目目标。

无法映射的域名保留为信源，不把域名自动变成连接器 ID。已识别但没有连接器的渠道仍可列入目标，后续覆盖记录明确显示缺少适配。

能力与资源分别判断：已部署连接器不等于当前项目能发布；还要读取当前格式验证、账号状态及项目资源范围。复用 `connector_capabilities` 与正式分发的资格判断，不另建更宽松的就绪标准。

## 项目目标写入

沿用 `ProjectSettings.distribution_scope` 和现有项目修订服务，不维护第二份发布目标真相。AI/UI 使用同一个严格、版本化命令，提交期望 revision、稳定幂等键及完整的目标范围，返回已持久化 revision 和范围。

不能在“添加一个建议”时，将 `AllEligible` 静默改为仅包含该渠道的 `Explicit`。保留未明确修改的排除项、资源池和复制策略；AI 先读取当前配置，按用户意图构造新范围。界面成功后读回相同持久状态。

## 后续周期应用

现有内存和 PostgreSQL `schedule_next_cycle` 均继承前序配置；仅调用项目修订并不能使新增目标生效。

后继创建须在项目锁内读取最新已保存分发范围。若与前序不同，复制前序配置，只替换分发范围，创建新的不可变配置 revision/hash，再绑定后继周期及其新清单。保持原时区、截止和周期安排语义；不可沿用旧估算并声称它已包含新增目标。

已有后继的幂等重放返回原后继，不追改。目标修改在后继创建之后提交时，进入再下一周期。前序配置、冻结清单、尝试及报告均不可修改。内存和 PostgreSQL 行为一致。

## AI 与冻结评估隔离

人类证据检查可查看已有权限内的冻结评估样本；优化工具仅返回明确允许优化的样本推导结果，未知用途保守排除。不能通过域名、引用 URL、样本引用或说明字段把冻结题目及逐题回答带入优化输入。

AI 推荐读取不直接暴露完整引用洞察 DTO。目标配置可供后续调度使用；如保存推荐证据，其审计记录与内容优化输入分开。

## 必须验证

- 精确映射、多域名去重、未归类信源、分页口径、夹具与无效搜索回执排除。
- 跨租户隔离；连接器可用与项目账号可用分开；不支持发布仍能查看建议。
- AI 输出排除冻结评估及未知用途的派生信息。
- AI 写入 → UI 读回同一范围；冲突保留原选择；同键重放、异请求冲突。
- 修改后创建的新周期引用新配置；旧周期字节不变；后继重放不变。
- 实际 PostgreSQL 重连、目标修订与周期创建并发、原时区和截止语义不回归。
- 显式不支持渠道仍保留覆盖缺口；支持渠道经过正常账号、预算和发送前校验。
