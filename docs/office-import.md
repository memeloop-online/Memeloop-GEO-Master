# Office 结构化资料导入

本契约细化 W03 中 DOCX 与 XLSX 的原件导入路径；不更改冻结产品规格。只有显式配置相应格式的服务端解析适配器，能力查询才声明可解析。上传完成或 P00 显式导入已提交附件仅代表任务受理，不代表检索证据已经形成。原件、SHA-256、作用域、来源用途与版本仍遵循 W03 基线。

## 独立格式协议

协议版本 `geo.office.parse.v1`，解析 profile `poi-5.4.1_ooxml-struct-v1`。解析服务是隔离适配器：服务端固定目的地址，原始已校验字节作为请求输入；不向服务交付会话、数据库凭据、对象存储密钥或客户可选目的 URL。每次响应须匹配原件 SHA-256、profile、协议版本、格式及 MIME。不执行公式、不抓取文档内外部资源、不启动宏、不自行补算或推断缺失单元格。

检查接口冻结格式明确的 `OfficeDocumentManifest`：DOCX 是按实际顺序编号、至多 64 个顶层 body element 的连续块，索引从零开始；XLSX 是某个实际工作表内至多 128 个真实行的有界行块，行号从一开始。一个解析单元是整个 body-element 块或工作表行块，**不是一个单元格、一个虚构 PDF 页面或一个全文件的无界任务**。单位清单的稳定 unit ID 从零递增，总数至多 20,000。已保存的清单不能在租约重启或重试时变更；不能通过遗漏超限单位而宣称整份原件已导入。

每单元输出必须采用一种格式专属结果：

- DOCX 段落保留顶层元素索引、原始段落索引、标题层级路径与实际文本；表格保留表格索引、行/列坐标、单元格文本及合并跨越元数据。无法准确表达的合并或嵌套结构要标记对应单元 `unsupported_content`，不能压平并伪造覆盖。
- XLSX 行保留工作表名与原始索引、实际行号、精确 A1 单元格坐标、原始类型及原始值、可选显示值。公式只保存原始表达式及原文件已有的缓存值和缓存类型；原件没有缓存就明确保持为空，不能制造零值。表头定位仅来自文件明确声明的工作簿表格元数据，逐行绑定；不能认为第一行是表头。
- 保留每单元原始解析输出并生成 Unicode 字符区间有界的检索片段。DOCX 证据定位到标题、段落或表格行列和合并信息；XLSX 证据定位到工作表/单元格及已声明表头。未提供的图形坐标、OCR 文本、结构化事实或向量匹配不得推断。

单元结果最大 4 MiB、文档合计结构化输出最大 32 MiB；越界必须显式失败并保留覆盖缺口。CSV 与 PDF 使用各自独立协议、错误及定位器，Office 不重用 PDF 页码状态。

## 持久工作流与恢复

上传路径和 P00 已提交对象导入都进入同一个有作用域、幂等的 Office 队列。完成原件校验后，接受事务将 Source、ImportJob、Operation、原件对象与解析输入绑定、受理回执及事件保存；不能在数据库事务中调用解析服务。扫描器按 `(created_at, job_id)` 稳定分页，先预留本地解析槽再领取有 TTL 与 fencing token 的租约。读取每个任务时重新校验对象元数据、原始字节 SHA-256、声明 MIME 和来源作用域；旧租约失效后不得续租、覆盖结果或发布知识版本。解析器忙、断线和超时保持持久进度，并允许原租约到期后重新领取，不虚构永久失败。

冻结清单后逐单元持久记录成功或固定失败码。成功单元在同一任务内不能覆写；重放相同结果幂等。发布时验证全部单元有明确结果，来源仍有效，原始对象与摘要仍一致。存在成功检索证据时形成新的不可变 SourceVersion、chunks 与 KnowledgeRelease，版本摘要**始终是原始 Office 文件 SHA-256**。部分成功发布带真实成功/失败单元计数；**零有效证据不发布新版本或 release**，原先可用版本保留。来源转内部或被撤销后，原有用途过滤即时生效；公开检索不能继续使用已撤销来源。

失败任务或部分成功任务的用户重试只继承之前真实成功的单元，失败/缺失单元进入新的 ImportJob、Operation 及租约；`resumed_from` 指向原任务。重试成功形成后继不可变版本和 release，旧证据与旧任务回执不被篡改。原任务进度读取不自动跳转新任务。完成读取核对任务、版本、原件、操作结果和 release 成员，且只返回当前作用域及用途可见的来源。

进度接口的 `completed_units` 和 `failed_units` 是实际结构单元数，不是 Office “页数”。错误仅返回固定码、格式及可选 `unit_id`（列表有界、总数独立记录），不回显文档正文、公式内容、文件路径或异常。文档错误：`invalid_docx`、`invalid_xlsx`、`encrypted_office`、`parse_failed`、`unit_limit`、`unsupported_content`；单元错误另包含 `empty_text`。原上传、对象导入与重试分别有稳定幂等身份。

## 验收边界

需明确验证跨作用域拒绝、原始 SHA-256 不可变、稳定检查清单、结构坐标和 Unicode 片段、公式缺缓存不捏造结果、表头不臆测、成功单元不覆写、租约过期 fencing、重启续跑、部分发布/零成功不发布、幂等重试与来源撤销。内存实现要与 PostgreSQL 使用相同协议及状态判断；真实 Java 解析集成、可丢弃 PostgreSQL 实库重启与浏览器路径须分别记录验证证据。未配置对应格式适配器时不得声明 DOCX/XLSX 已解析；OCR、原件高亮、结构化事实、向量、外部发布和真实客户材料都不属于此契约完成声明。
