# 单篇内容分发接入

本文细化 `seo-geo-delivery.md` 的单篇发布实施契约，不修改冻结产品规格。
实际交付证据与未完成事项分别见 `WORKLOG.md` 和 `TODO.md`。

## 用户路径

用户在 AI 工作台指定已保存的正文版本与发布账号，或在内容详情选择账号后发布。
两者调用同一 Rust 服务，不修改项目后续默认渠道，不要求创建额外周期，也不新增审批。
编辑器有未保存修改时，发布对象仍是明确选择的已保存版本，不能隐式混入草稿。
请求受理后保留请求 ID；刷新、返回或读取进度不再次提交。

## 接口与身份

均位于 `/api/v1/projects/{project_id}`，沿用会话、项目权限、CSRF 和禁止缓存策略。

| 接口 | 职责 |
|---|---|
| `POST /content-distribution-requests` | 固定正文版本与账号，持久受理并尝试物化；返回 202 不表示已发送 |
| `GET /content-distribution-requests/{request_id}` | 读取同作用域不可变请求和已关联意图 |
| `GET /content-distribution-requests/{request_id}/publication` | 读取真实渠道目标、尝试、结果与夹具标记，不启动发送 |

POST 必须提供 `Idempotency-Key`；请求体仅含 `content_asset_id`、
`content_revision_id`、`account_id`、`placement_slot`、`format`。
平台与账号归属从服务端解析，调用方不能指定运营商、租户、成员或提权字段。
账号可以是客户自有账号或已经分配给当前项目的运营池账号。
相同键与相同冻结输入复用请求；同键异请求冲突。
超时重试保留原键及原正文/账号，不把最新编辑版本替换进原请求。
已受理请求按作用域与原键先读取、逐字段比较；账号随后撤销不妨碍读取原回执，
但不恢复发送权限。同键改变正文/账号等输入仍返回冲突。
页面在发送前将待确认请求的键与资源 ID 保存在当前标签页的 sessionStorage，
按用户、运营商、租户、项目和内容资产隔离，不保存正文或凭据。
刷新后只能显式重试原请求或开始新请求，不自动重发；取得匹配回执后清理。

P00 使用 `content.distribute.request.v1`、`content.distribute.read.v1`，
归属 `geo.hostops.v17`，共 45 项工具。Host bridge 注入作用域，输出有界资源和账本摘要，
不向模型提供账号秘密。部署时 API、工具 bundle 与摘要必须同时匹配。

## 一份发布账本，两种来源

`ContentDistributionRequest` 是冻结的分发请求，不是另一份发送状态机。
`PublicationBundle.origin` 区分：

- `CoverageTarget`：既有周期分发覆盖项；
- `ContentRequest`：独立单篇请求。

两者共用变体、逻辑发布意图、持久 outbox、渠道目标、发送尝试和只读查回。
逻辑发布身份沿用既有算法，不引入请求 ID 或周期 ID，避免换请求或换周期重复发送。
新请求可以关联已有在途、未知或已验证意图，不改变原始来源及原发送记录。

旧 `PublicationIntent.channel_target_id` 与 `PublicationCommand.target_id`
是历史覆盖来源投影，不是实际发送目标。独立请求的旧投影为空 UUID，
不能据此构造页面链接或查找发送记录。
实际渠道目标通过 `PublicationCommand.command_id` 读取。
权威来源为 typed origin 及相应的数据库外键，不创建伪覆盖项或伪周期。

迁移 0038 为意图和命令增加作用域内请求来源外键，要求目标来源/请求来源恰好一个。
既有覆盖行不重写；独立生成发布目标允许 `cycle_id=NULL`，
原发布计划和独立测量的所有权约束保持不变。
旧生成目标未携带请求来源时仍按原结构解码，缺省字段不参与旧序列化身份。

## 物化与恢复

PostgreSQL 按项目锁、请求行锁及依赖检查的顺序处理：

1. 读取已受理请求及精确正文版本；
2. 重新校验项目、账号、独立内容检查、当前公开证据和连接器格式能力；
3. 生成/复用确定性变体和逻辑意图；
4. 仅在没有既有意图时创建原 outbox 命令；
5. 同事务关联请求与意图。

不是仅凭正文没有阻断项就认定通过独立检查。发送前仍重新读取当前依赖，
不能用受理时的账号/来源快照绕过撤权或来源用途变化。
项目不存在与暂停/归档分别处理；独立请求不以人为启动周期作为前提。
富文本和媒体尚未贯通正式发送时明确不可用，不静默降为纯文本。

HTTP 持久受理后即使物化失败，也保留稳定请求 ID，不把已经受理的请求表现为不存在。
后台恢复器分页扫描未关联请求，失败行不阻塞后续页；完整一轮结束后再等待重试，
不将每一页固定休眠变成吞吐上限。
重启重新读取持久记录，不重建请求，不直接调用外部发送器。
多个副本通过同一原子物化与现有发送领取机制协作。

迁移 0039 保存可选 `materialization_deferral` 投影：固定枚举原因、失败次数与下次重查时间。
仅使用项目暂停、账号不可用、连接器不可用、正文未就绪、来源不可用、
格式不支持、临时失败和内部错误八类，不保存或展示 SQL/供应方异常原文。
诊断不进入受理身份/摘要；不会把失败物化记成发送失败或生成新意图。
PostgreSQL 在原物化事务退出后条件更新未关联请求，成功关联清空诊断，
迟到的失败不能覆盖已关联结果。退避从 2 秒递增、上限 5 分钟，不形成永久停用。
恢复扫描约每 2 秒读取到期行，按原 UUID 游标分页；条件恢复后复用原请求继续。
UI 轮询未关联回执，显示原因与下一次自动检查时间；P00 读取同一投影，
取得发布意图后停止使用旧等待原因，继续展示真实发送账本。没有新增人工放行。

内存装配使用同一份已受理请求存储和各 AppState 自己的不可变权威引用快照。
替换正文、账号、连接器或发布仓库后重新绑定检查依赖，不丢失已受理请求，
也不改变兄弟 AppState 的依赖。读取当前资料/账号不持有请求写锁，
最终关联按请求到发布仓库的顺序串行；真正发送前仍重新检查依赖。

## 展示、报告与未完成边界

页面分别展示请求受理、实际尝试、平台接收、公开验证和未知结果。
夹具结果明确标为测试，未知结果不宣称正在查回，除非有相应查回任务证据。
单篇请求不能改变已冻结的周期报告分母；独立发布的报告列项与 SEO 观察仍需后续接线。

以下事项不能从接口或单元测试通过推导为完成：

- 自动恢复的大规模积压、多副本故障注入及真实依赖恢复验收；
- 内存模式重启不持久，实际部署仍使用 PostgreSQL；缺少权威检查时拒绝物化；
- 首次真实创作者账号发布、匿名全文读回及发布因果证据；
- 富文本/图片正式载荷、共同周报与外部公开资产 SEO 观察；
- 多副本、百次每秒发送目标、故障恢复和容量验收。

测试数据库必须与演示业务数据库隔离。全局 outbox 扫描会看到同库其他测试行，
关联测试的简化夹具不得留下不可解码的可执行命令。
