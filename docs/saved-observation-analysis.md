# 已保存测量记录的解析

## 核心流程

原始平台响应保存后，通过项目“模型与 AI → 测量结果解析”配置调用模型，取得答案、引用和推荐对象。解析不向被测平台重新提问；平台会话清理后仍可读取本系统的存档。

自动解析与用户选择“重新解析”共用持久任务。页面关闭不取消后台任务。重新解析创建新的分析结果，不修改原问题、采样时间或原始响应。

## 当前接口

- `GET/POST /api/v1/projects/{project_id}/channel-targets/{target_id}/attempts/{attempt_id}/analyses`。
- POST 接收 `idempotency_key` 和可选 `capture_id`；其他来源信息由服务读取，不要求用户填写。
- GET 返回分析结果、可解析来源和分页游标。
- 仅使用当前 prompt `geo.observation.extract.v4`、parser `geo.observation.extract.v6`。旧 schema 分派、直接临时推理路径和旧数据兼容不再保留。
- AI 负责理解原文与提取语义。执行器核对原文引用，不使用供应商内容规则或名称正则解析器。推荐对象契约见 [recommendation-measurement.md](recommendation-measurement.md)。

### 提示准备

当前来源的提示统一由执行器中的 MJS `extractionPrompt` 准备。Rust 通过既有鉴权客户端调用
`POST /v1/observation-analyses/prepare`，请求为 `source_json`、`source_sha256`、
`prompt_version`、`parser_version`；响应为 `prompt` 及相同摘要和版本。
端点只处理保存的来源字节，不打开浏览器、不调用模型。原始消息索引、可见正文、
采集状态和脱敏说明保留，模型凭据仍由 Rust 管理。准备失败不进入推理。

提示准备和结果核对仅接受显式当前版本，未指定版本及旧格式均拒绝，不进行兼容分派。
部署时先更新执行器端点，再更新依赖该端点的 API；先升级 API 会导致准备失败。

## 执行与恢复

1. 自动受理复用同一来源的任务；手动受理在一个事务中创建分析版本和关联任务。
2. 后台领取 queued 任务并调用模型。响应持久化后，只继续结果处理，不重复推理。
3. 若原文已保存而入队尚未完成，来源恢复扫描补齐当前任务；已经有任务或可信结果的来源不再次推理。
4. 未确认结束的 running 调用不盲目重发。任务失败可用已保存原文重新解析，不需要再次进行平台测量。

删除了历史版本分页协调和 `GEO_OBSERVATION_HISTORY_ADMISSION` 开关。当前来源恢复随服务启动，不需要用户或运营人员额外操作。

解析模型预算由部署配置 `GEO_OBSERVATION_MODEL_TIMEOUT_SECONDS` 指定，默认 300 秒；这不是用户额度或测量数量限制。租户／项目作用域、任务领取和真实数据存储仍由服务负责。

### 自动受理回执

执行器调用 `POST /internal/v1/observation-ai/extract`，提交已存来源的票据、ID、摘要及当前提示版本。接口在持久任务受理后返回 `202 {"status":"accepted","intent_id":"…"}`，不等待模型正文，不接收 `wait_budget_ms`。这只表示后台已接管解析，不表示答案已经验证。

执行器收到受理回执后保留来源和会话归属证据，按现有流程释放浏览器并进行平台会话清理；原始执行使用 `extraction_pending` 原因，不伪造回答。既有分析接口的 `extraction.state` 与解析版本提供后续进度和结果，原始回执不被改写。接入账号优先解析仍遵从项目配置，已取得有效结果时不再向配置模型重复受理。

API 与执行器须配套升级；受理请求和响应仅保留上述当前契约。部署期间排空活动测量，再切换两端并恢复派发，避免混用同步正文响应与异步受理响应。

## 结果与报告

保存答案、引用、推荐对象、实际模型、用量和分析时间。提取失败不冒充无推荐；不能用请求模型名称填补未取得的实际模型信息。推荐字段不可用时应保留有效答案与引用。

信源和报告读取同一次执行的有效结果，不把多个分析版本当成多次测量。较新的失败分析不抹除已取得的答案。报告保存自己的时间范围和分析依据；问题集不同、采样条件不同的记录不直接混算排名变化。

解析完成和平台会话删除分别验证。解析数据不能代替会话归属或清理结果。

## 自测

- 实际问题 → 原文存档 → 自动解析 → 推荐／答案／引用 → 页面刷新读回。
- 同一问题集多次采样归组；临时采样保留独立单次结果。
- 页面断开后继续完成，响应存档后恢复不重复推理。
- 模型失败、无推荐、未明确排名分别展示。
- 资料与账号跨项目隔离；平台会话清理后存档仍可读取。

诊断可设置 `RUST_LOG=geo_api=info,geo_provider=info`，只记录阶段、状态和耗时，不输出凭据、端点、正文或账号信息。当前实现／部署状态以 [HANDOFF.md](HANDOFF.md) 和 [WORKLOG.md](WORKLOG.md) 为准。
