# 已保存测量记录的重新解析

## 用户流程

在测量记录详情中，存在已保存原始响应时可选择“重新解析”。服务使用项目“模型与 AI → 测量结果解析”的 API 模型，不再向被测平台发送测量问题。答案、引用、解析模型和时间独立保存；原测量状态、采样时间和统计分母不改变。

实时测量仍可优先使用已登录网页账号解释回答。历史重解析本增量只使用项目 API 解析路由，不能将其描述为重新测量或新的平台反馈。

## 服务与证据

- 用户接口：`GET/POST /api/v1/projects/{project_id}/channel-targets/{target_id}/attempts/{attempt_id}/analyses`。
- POST 只需 `idempotency_key`，可选 `capture_id`；服务从持久记录确定来源、摘要和原采样时间，不要求用户填写技术字段。
- GET 返回可解析来源、分析版本及游标。按创建时间与版本 ID 倒序稳定分页，最新版本保持可见。
- 解析提示词复用实时解析模板。AI 解释内容语义，执行器端仅复用原文定位与结构核对；没有供应商内容规则解析器。
- 服务内部通过认证的 `/v1/observation-analyses/ground` 核对模型候选与原文字节摘要。该端点不打开浏览器、不访问供应商、不持有用户登录态。
- 来源必须与租户、项目、目标、执行和账号绑定。执行或解析配置失败形成的 unknown 不应掩盖已经独立持久保存的真实来源。发现来源按持久 capture、身份、摘要、时间与可信回执验证，不按失败描述字符串放行；明确的夹具、注入或冲突来源仍不可当成真实证据。原始响应证据本身不可借此绕过独立 capture 校验。
- 保存实际解析模型、项目配置修订、用量和独立结果；未通过核对时不展示候选内容为已确认答案。隐私字段过滤与实时解析共用。

## 幂等、中断与恢复

手动解析持久化增量已在工作区实现，待独立审查、组合 CI 和部署；以下为该增量的实施契约，不能据此认为线上已切换。

- POST 在同一事务中创建解析版本及关联持久任务，不再启动脱离调度器的临时推理。相同提交键返回原版本；不同提交键创建显式新版本，不采用已有自动任务冒充新版本。
- 支持持久 capture 和执行记录中的原始响应证据，分别使用既有终态来源验证。自动任务的旧键保持不变；手动任务以版本和完整来源绑定独立命名。
- 已关联持久任务的版本不再适用旧手动路径的 150 秒外层截止或 GET/POST 触发的 180 秒中断。模型预算由共同后台解析配置决定；关闭页面或停止等待不取消任务。
- 原子领取、响应 checkpoint、结果投影及中断同步更新同一个解析版本。已保存响应只恢复核对，不重复推理；未知在途推理不自动重领。迟到写入不能绕过领取凭证。
- 旧版未关联任务的记录保留原有保守中断规则；重复提交旧键不会补建任务或重发未知推理。显式新版本不改写旧失败、原采样状态或报告分母。
- 上线先应用迁移 0062，再切换 API。迁移只扩展来源和版本关联，不重写已有任务键、不自动接管旧临时调用；须先核对旧调用与发布期间在途任务。

解析恢复不授权远端会话删除；平台清理仍依据独立的已存档数据和会话归属证明。

### 实时与后台共用持久解析任务

持久任务与后台预算已部署；历史自动入队及并发协调已通过组合 CI 并合并，部署切换待完成。手动持久任务增量状态见上节。实时等待超时或客户端断连不证明上游推理已停止；不得在此时无条件再调用一次模型。

- 实时回调验证已保存来源与凭证后，创建或复用持久解析意图。唯一绑定包含租户作用域、目标、执行、来源标识及摘要、提示词／解析器／自动策略版本；系统自动键与用户提交键分命名空间，不仅按正文摘要去重。
- 回调只等待同一任务，独立调度器原子领取 queued 意图并发起一次推理。回调停止等待不取消后台任务，也不创建第二次推理；网页账号和浏览器资源照常释放。
- 后台测量解析使用独立模型调用预算，默认 300 秒，由服务端 `GEO_OBSERVATION_MODEL_TIMEOUT_SECONDS` 配置为正数且可表示的秒数。继承、自定义和租户路由均须透传同一预算及原作用域检查；网页回调等待仍独立结束，工作台原有预算不变。预算耗尽保留中断状态，不自动重复推理。配置只属于部署，不增加用户设置步骤或任务数量限制。
- 模型响应、实际模型、配置修订和用量先保存，再进行原文核对。已保存响应的核对与投影可以恢复，不需要再次推理。
- 实时阶段尚无终态回执，先使用来源回调的完整来源认证；投影独立结果前必须再通过现有终态来源验证器，不能绕过执行、身份或摘要约束。
- 启动及周期分页扫描恢复 queued、已保存响应但未核对／投影的任务。queued 不因等待超过旧 180 秒窗口而被丢弃；过期 running 不自动重领，以免重复计费。没有上游请求查询能力时，进程在出站后死亡只能明确记为中断／未知，不承诺恰好一次且必成功。
- 历史补齐复用既有有效解析；没有有效解析的合格来源至多创建同一自动意图。切换前须确认旧版直接回调的在途推理已经结束，不能将网页等待窗口当作出站调用结束证明。
- 保留原 unknown、来源字节、旧解析、采样时间和报告分母。解析完成不产生远端清理权限，不要求用户逐次确认或手动启动后台续接。

验收包括：超过实时等待窗口仍只调用一次模型；并发提交／扫描不重复领取；旧 queued 跨重启恢复；响应 checkpoint 后只恢复核对；出站后进程中断不盲重试；迟到写入受 claim 约束；跨租户同摘要、冲突来源、旧成功及晚到回执分别处理。

### 历史自动补齐的实施与上线顺序

- 自动入队复用同作用域、执行和来源任意版本／状态的既有意图；显式手动重解析仍可创建新版本。手动调用尚未确定结束时，自动扫描等待，不将超时或租约到期当作推理取消。
- 迁移 0060 为手动解析增加 `inference_resolved`；旧记录默认未确定。实际模型响应或已确认的本地调用前失败才建立结束证明，已完成 grounded／unverified 结果自身可证明结束。
- 数据库以作用域内执行行作为共同锁，协调手动生命周期与自动入队；内存实现使用共享 gate。历史扫描分页前保存生命周期快照，最终入队原子比对；期间发生手动完成等变化时重扫，不根据过时快照发起推理。
- 后台按固定截止和 UUID 游标续扫，每轮最多处理 16 个来源、每页 100 个解析版本；这是调度批次，不是用户额度或历史总数上限。已有 queued／响应 checkpoint 恢复不依赖历史扫描开关。
- 先应用迁移 0060，再部署新 API。确认旧版直接调用已结束后，由部署配置启用 `GEO_OBSERVATION_HISTORY_ADMISSION`（默认 false）；用户不需要配置或确认。该配置只控制遗留来源自动发现，不中止现有任务。
- 上线验证分别覆盖任务恢复、历史复用、手动并发、结果投影与供应商会话清理；解析成功不证明远端会话已清理。

### 失败含义

持久失败代码区分来源不可读、模型未配置或访问被拒、上游 HTTP 状态、传输失败、响应格式不支持、超时及原文核对服务不可用。页面使用固定中英文提示，不回显上游错误正文；服务不可用不会一律要求用户重填密钥。未知或旧版原因保留一般失败提示，不能根据耗时猜测故障。

未收到可规范化的模型完成响应时，实际模型仍为空，不能用请求模型或设置页默认值补齐。已收到响应但后续候选或审计校验失败时，保留合法的实际模型、配置修订与用量，丢弃不合格候选。输出截断、过大、工具调用或无效内容分别记为未核验，不转成已确认答案。这些诊断不会自动再次调用模型。

## 信源和报告投影

信源与渠道建议读取当前执行的一个有效回答：有来源核验通过的已完成解析时，采用截止时刻内最新的有效解析，否则保留原有可信观测。较新的失败解析不抹除旧有效解析，同一问题的多个版本不合并引用或重复计数。展示独立的解析计数、模型、时间和版本依据，原执行状态和统计分母不变。优化用途仍按不可变问题用途与项目作用域过滤。

报告将这类结果放入独立的 `supplementary_measurements`，不加入冻结测量目标的分母。独立话题须落在报告的采样窗口；原始来源保存时间及解析完成时间都不能晚于报告证据截止。截止后完成的解析只进入后续显式更正，不能回填已保存的首版报告。预览、CSV 和 PDF 使用同一份独立证据与实际模型出处；旧快照重放保持原样。

数据库按指定执行批量选择最新有效解析，来源绑定和字节摘要由共享只读服务复核。索引可用性回归不代表总体吞吐或百万记录容量已验收。

## 验收范围

需分别验证来源发现、跨项目拒绝、重复提交、失败与中断、答案/引用核对及刷新后持久读回。自动化回归不替代真实演示；单次离线解析成功不代表用户界面的闭环已完成。

## 阶段诊断部署

部署阶段诊断时必须配置 `RUST_LOG=geo_api=info,geo_provider=info`；仅启用 API info 会遗漏供应方阶段。日志只输出固定阶段、状态、耗时和本地随机调用标识，不输出凭据、端点、正文或账号信息；该标识不能关联网关请求。未完成 future 的析构仅表示未完成，不能直接解释为超时或推断出站阶段。

本增量不改变超时、模型预算或重试策略，也不自动发起模型调用。实现及两轮审查完成不等于故障原因已确定；部署并确认日志级别后，仅执行一次有界的已存来源重解析，保留原执行及旧解析结果，不向消费端重新提问。
