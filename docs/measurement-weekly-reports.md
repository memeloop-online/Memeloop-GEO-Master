# 独立测量自动周报

产品基线不变。本增量已随 PR #64 通过双平台 CI、两轮审查并部署，迁移和后台自然周排期已核验；自然到期生成仍待实际验收。当前交付状态见 `HANDOFF.md`，待办见 `TODO.md`。

## 用户流程

用户直接测量任意话题，无须上传企业资料或启动优化周期。项目现有的报告时区和周报时间同时用于独立测量周报。到期后，系统将该自然周的 AI 测量与传统搜索记录汇总为已有的独立测量报告；用户在现有报告页查看，P00 读取同一资源。

生成报告只读取系统内已保存的证据，不再向 AI 平台提问、不调用搜索供应商，也不创建占位优化周期。没有样本时如实呈现空报告。

## 排期与恢复

- 首次发现项目时创建下一次报告排期，不为安装前的所有空白历史周追溯生成。
- 自然周为项目时区的周一零点至下周一零点，半开区间。
- 排期同时保存 UTC 窗口、时区、周报配置、报告时间和证据截止。报告时间与截止均到达后才生成。
- 现有待生成排期保持冻结；完成后，后续排期使用项目当时的配置。时区变更使用新时区完整自然周，允许与此前 UTC 窗口重叠或留空，不生成过渡周。
- 进程晚启动或执行失败不重算已冻结窗口；实际生成时间与证据截止分开保存，晚于截止的证据不因延迟执行而进入该报告。
- 复用现有每分钟后台扫描，逐页处理项目。每个项目每轮推进一个已排期周，历史积压在后续轮次继续；单项失败不阻塞其余项目。
- 报告保存后才写入排期的完成关联。若中间退出，下轮复用已保存的不可变报告，再补完成关联。
- 草稿、活动及暂停项目可生成只读周报；已归档项目不创建或选取新排期。归档前已被调度器选中的只读报告可以完成并保存关联，不留下已存报告却未关联的悬挂状态。

## 实施入口

- `crates/domain/src/measurement_weekly.rs`：独立自然周及排期时钟计算。
- `crates/persistence/src/measurement_weekly.rs`、迁移 `0063`：持久发现、到期扫描及完成关联。
- `crates/app/src/measurement_weekly.rs`：后台调度，复用现有报告保存服务。
- `crates/api/src/measurement_reports.rs`：按冻结截止收集 AI／搜索证据，保持实际生成时间。
- 原报告 API 和页面保持不变，不新增强制设置或用户确认。

同窗口已存在手动首版且证据截止不同的情况，当前返回冲突并保留排期，不覆盖原报告、不冒充自动生成完成。统一手动与自动窗口的版本策略保留后续待办；正常自动排期不依赖该扩展。
