# PDF 文字资料导入

本文件细化 W03 的文字型 PDF 导入路径，不修改冻结产品规格。实际验证结果见 `WORKLOG.md`；DOCX、XLSX、OCR、正式对象存储及完整 W03 仍是独立未完成项。

## 用户路径

配置解析服务后，P03 上传 PDF，或在 P00 显式导入已上传 PDF 附件，均进入同一后台任务。上传完成不等于知识已经可用：受理结果只有原件、来源和解析任务，页面自动刷新运行中的状态。

后台按原始页码保存文字或失败原因。已经成功的页面可以形成标注覆盖缺口的知识版本；失败页可从资料详情重试，不要求重新上传，也不要求人工批准。重试后的可用结果形成新版本，不修改已被问答或内容引用的旧版本。

扫描图片页显示需要 OCR，空白页显示无可提取文字。当前不会生成图像描述、推测页码、伪造文字或把所有页面都算作成功。PDF 表格结构、版式还原、原件高亮预览和扫描件识别尚未完成；当前提取的是文字层。

### P00 自动接续：下一实施切片，尚未完成

当前 `agent_runtime.rs` 的附件导入投影没有返回解析 job ID，worker 结果 DTO 也尚无该引用。后台解析完成不能据此自动恢复正在等待的 MemeLoop 阶段；直接 runner 没有 phase-resume 入口。

不依赖上游修改的下一最小切片是明确标识的“资料完成后自动后续回答”，不是原 Run 中途恢复：

- 在显式导入边界保存原 message/turn/run、工具调用、job 集合及回答目标；与入队原子保存，或先保存可对账意图，避免任务先完成而关联丢失。
- 复用解析完成事务中的 ready/partial/failed outbox，并增加分页补偿扫描。按稳定依赖身份去重，只创建一次后续 queued run。
- 后续 turn 具有明确系统 origin/causation，UI 显示“解析完成，自动接续”；不得伪造一条用户消息。仅允许读取已绑定 release/version 并检索回答，不重新取得附件导入或原任务全部写操作权限。
- 创建 continuation、run 和会话事件同事务；沿用会话串行。原请求取消抑制关联接续，部分成功/全失败按实际结果回答，不伪造引用。

实施接缝为 `crates/api/src/agent_runtime.rs`、`crates/worker/src/host.rs`、Agent 仓储/dispatcher、PDF 完成 outbox 及 P00 事件呈现。验收须覆盖页面关闭、完成早于关联、乱序重复事件、多副本、事务边界重启、取消竞争和跨租户隔离。该方案解决后续任务入队恢复，不解决新 Run 的 running 阶段崩溃；完整同 Run 恢复仍按 `agent-tool-ledger.md` 的依赖推进。

## 存储与调度

1. 上传按原有流程核验大小、SHA-256 和作用域，保存原始对象。PDF 入队事务同时保存 Source、ImportJob、Operation、解析输入绑定和受理回执；不在 SQL 事务中调用解析服务。
2. 调度器分页发现待处理或租约已过期的任务。按服务声明的解析容量先预留本地执行槽，再原子领取并读取原件；不同任务可独立运行，没有新增全局 Agent 并发准入门槛。多副本竞争由服务实际执行槽返回繁忙并延后，不把健康检查中的容量当作空闲槽数。
3. Rust 校验原件摘要，向隔离解析服务发送本任务的字节。服务不能取得数据库凭据、存储 key、账号会话或来源 URL。
4. 先冻结页数与解析 profile，再逐页保存结果。每次写入核验租约身份和 fencing token；续租失败即停止后续调度，旧执行者不能覆盖新执行者。
5. 成功页面保留原始提取文字。知识片段按 Unicode 字符分段，定位为原 PDF 页码和提取文字内的字符区间，不声称拥有 PDF 坐标框或 OCR 结果。
6. 完成时创建不可变 SourceVersion、chunks 和 KnowledgeRelease。SourceVersion 的摘要始终是原始 PDF 字节摘要，不是提取文字摘要。来源状态和用途仍由现有知识授权规则约束。

迁移 `0026` 保存解析任务、冻结页数、逐页结果和租约。当前沿用内存或 PostgreSQL blob 原件存储，不能据此宣称 S3/MinIO 对象存储已经接通。

## 重试与部分结果

- 服务暂时不可用、连接超时或繁忙不生成假失败页面；任务保留持久进度，等待租约恢复。
- 格式损坏、加密、无法提取文字和输出过大使用固定错误码，不把解析器异常、正文或文件路径返回客户。
- 页面成功后不可在同一任务中覆盖。部分失败重试复用成功页，仅重新处理缺失或失败页。
- 全部页面失败时没有新的知识版本或 release；原先可用的知识不因此被删除。
- 部分成功形成明确的覆盖结果；补齐后生成后继版本，旧 release 和旧证据保持不变。
- 资料详情中的重试是用户可选的故障恢复操作，不是正常发布或资料生成的审批步骤。

## 解析服务

服务目录：`services/document-parser/`。使用 Apache Tika 3.2.3、PDFBox 3.0.5，固定 profile 为 `tika-3.2.3_pdfbox-3.0.5_text-v1`，协议为 `geo.pdf.parse.v1`。产物保留依赖的 LICENSE/NOTICE。

- `GET /health`：固定协议、profile 及实际配置的解析容量 `capacity`（1–64）。
- `POST /v1/pdf/inspect`：原始 PDF 字节 → 原始摘要及页数。
- `POST /v1/pdf/pages/{page}/parse`：同一原始 PDF 字节 → 原始摘要、实际页码和文字或明确缺失原因。

Rust 拒绝不匹配的摘要、profile、协议或页码，禁止 HTTP 重定向。目的地址只能来自服务端配置，不能由导入文件或请求覆盖。

单文件仍遵循 100 MiB 上限。当前解析 profile 另有 10,000 页、每页 4 MiB UTF-8 文字、整份文档 32 MiB 文字的处理边界，超出项明确记录为缺口；单页隔离 PDF 还有服务端资源边界，详见服务 README。服务忙时延后，不换成其他解析器后继续冒用原 profile。

## 启动与验证

开发依赖可按需启动：

```powershell
docker compose --profile document-parsing up -d --build document-parser
$env:GEO_PDF_PARSER_URL = "http://127.0.0.1:18081"
```

随后按 `HANDOFF.md` 启动 Rust 应用。Compose 中解析服务使用独立无外部出口网络、非 root 用户、只读文件系统及临时目录；不公开到所有宿主接口。不配置该变量时，现有文字/Markdown/CSV 路径不受影响，PDF 仍明确显示缺少解析能力。

CI 构建 Java 21 服务，执行真实合成 PDF 测试，上传可供开发复用的 JAR；另启动该 JAR，显式执行 Rust 上传到知识版本的真实 HTTP 集成测试。PostgreSQL 的 `pdf_parse` 套件使用可丢弃数据库验证持久进度、作用域、租约及部分重试。模拟解析结果的仓储测试不能代替真实服务集成测试。

### 复用 CI 产物

成功的 CI run 提供 `document-parser-java21-<完整提交 SHA>` artifact，包含 `document-parser-1.0.0.jar`。使用 `gh run download <run-id> --name <artifact-name> --dir <本地缓存目录>` 下载，记录来源 run 与提交；无需本地 Maven 编译。Java 21 或以上可执行 `java -jar <JAR 路径>`，默认仅绑定 `127.0.0.1:8080`；开发时设置 `GEO_PDF_PORT=18081` 避免与应用端口冲突，再配置 Rust 的解析器地址。

独立 JAR 只是本地开发方式，不带 Compose 的容器文件系统与网络隔离。生产须使用隔离部署；客户端文件不能改变 Java 命令、classpath 或解析服务目的地址。

每个解析请求在独立子 JVM 中执行，环境清空，仅保留必要系统变量；原件由 stdin 传入，stdout 有界，异常详情不外泄。监督进程在 20 秒截止后强制结束并回收子进程，再释放解析槽；Rust 请求截止为 25 秒。1 GiB 开发容器配置一个解析槽，增加槽数须同时增加 JVM 与容器内存，不影响 Agent 运行并发。

仍须注意：客户在原件上传后断开连接，不保证立即取消解析；该任务仍受上述 20 秒子进程截止约束。容器资源与无外部出口配置须在实际部署环境另行验收，不能用本地 JVM 测试代替。
