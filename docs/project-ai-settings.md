# 项目模型配置

## 入口与用途

项目设置的“模型与 AI”标签页使用 `settings?tab=ai` 深链，原账号管理入口不变。

两种用途分别保存配置：

- `workbench_content`：AI 工作台与内容生成。
- `observation_analysis`：解释已采集的测量响应；不是选择被测 AI 平台。

每种用途可以继承服务端默认路由，或配置 OpenAI 兼容连接地址、API Key 和模型。默认路由按当前项目的实际授权显示；存在全局 Provider 不表示所有项目都有模型权限。没有模型名称时可以显示默认路由已配置，但不能编造名称。

解析用途默认优先使用已连接账号，无法完成时才使用配置的 API 解析模型；关闭该偏好后直接使用 API 解释原始响应。两种方式都不改变被测平台、问题、观测面或原始采集结果。

## 保存与测试

- 管理员修改配置；有项目访问权限的其他成员只读。
- 密钥只写入加密存储，不通过读取接口返回，也不保留在保存后的表单中。
- 密钥留空表示保留已有值；切回继承模式会清除自定义凭据。
- 版本冲突保留本地输入，不覆盖另一个操作的配置。
- “测试连接”和“获取模型列表”使用已保存版本，无需再次输入密钥；有未保存修改时先保存。
- 模型发现失败仍可手动填写模型标识。测试失败显示可执行的简短原因，不回显上游响应体。
- 配置在下一次调用时读取，不需要重启进程。已经发生的调用不会因改配置而撤销或重发。

接口根路径：`/api/v1/projects/{project_id}/ai-settings`。

| 请求                   | 作用                              |
| ---------------------- | --------------------------------- |
| `GET /`                | 两种用途及其有效默认配置          |
| `GET /{usage}`         | 单用途配置，不含密钥或密文        |
| `PUT /{usage}`         | 带 `expected_revision` 的条件更新 |
| `POST /{usage}/test`   | 使用已保存版本执行有界模型调用    |
| `POST /{usage}/models` | 使用已保存版本读取真实模型列表    |

读取及修改响应禁止缓存。身份、租户、项目及角色由现有认证边界提供；模型不能自行指定凭据或扩大作用域。

## 后端与执行器

配置仓储使用迁移 `0044`。密钥复用现有持久加密材料，但 AAD 独立绑定项目和用途；日志与错误不得包含密钥、连接地址或上游响应体。

动态模型桥在自定义模式使用当前配置，在继承模式保留原来的作用域模型路由。解析用途继承原始服务端路由，不继承另一个用途的自定义密钥。

实时解析在保存原始证据后，通过固定内部回调取得项目偏好并调用模型。请求只提供服务票据、持久证据引用及摘要，不接受任意提示词、模型、地址或密钥覆盖。票据绑定确切的账号、会话、执行和项目；来源摘要与 capture 封装摘要分别校验。Rust 与执行器共享提示词模板，AI 判断响应语义，现有执行器只核对结构和原文定位。

执行器没有回调时，仅显式开启 `GEO_OBSERVATION_AI_LEGACY_ENABLED=true` 才允许旧环境解析配置；已经绑定回调的任务不能绕过项目配置回退到环境凭据。

未配置默认模型时，镜像内经过摘要验证的 Agent bundle 仍可加载，以便之后保存项目连接即可使用。非镜像开发环境可用 `GEO_PROJECT_AGENT_BUNDLE_PATH` 与 `GEO_PROJECT_AGENT_BUNDLE_SHA256` 指定同一受信 bundle；这两个配置不携带模型密钥。

## 验证与尚未覆盖

自动化验证覆盖加密及用途隔离、版本冲突、凭据留空/替换/清除、管理员修改、真实模拟 HTTP 测试及模型列表、动态切换模型、默认授权和解析回调绑定。

真实部署后的保存、刷新、模型调用和解析结果仍须分别验收。已存证据的不可变重分析仓储属于另一条能力，只有仓储实现不表示用户已经能通过界面重分析历史记录。
