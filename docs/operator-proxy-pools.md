# 运营代理池

本增量提供代理配置的持久管理，不改变现有账号网络。账号固定绑定、实际出口检查及历史任务路由接续仍按 `operator-account-onboarding.md` 实施；不将保存配置视为连接成功。

## 操作与接口

资源管理员在运营账号池页面展开“代理池”，创建池、添加代理或编辑配置。仅运营管理员和资源管理员可访问，服务端仍按配置的资源租户及当前成员资格校验。

| 路径（前缀 `/api/v1/operator`） | 操作 |
|---|---|
| `/channel-proxy-pools` | GET 分页、POST 创建 |
| `/channel-proxy-pools/{pool_id}` | PATCH 名称或启用状态 |
| `/channel-proxy-pools/{pool_id}/members` | GET 分页、POST 添加代理 |
| `/channel-proxy-pools/{pool_id}/members/{member_id}` | PATCH 名称、启用状态或替换代理 |

列表参数为 `limit`（默认 25，最大 100）和 UUID `cursor`；响应为 `items`、`next_cursor`。所有查询限定 operator，不能凭其他运营商的标识读写。

创建池输入 `name`。创建成员输入 `name`、`proxy: {server, username?, password?}`。修改要求 `expected_version`，并发修改返回冲突，不覆盖新版本。HTTP(S) 使用有效端口，SOCKS5 要求显式非零端口；地址不含认证、查询、片段或路径，认证字段单独提交。

响应提供资源标识、名称、启用状态、版本和时间；成员另提供当前 `revision_id` 和去除认证的 `proxy_server`。没有读取密码或解密凭据的 HTTP 接口。地址仅对运营资源管理员可见，不进入客户项目投影。

## 持久化与恢复

- 迁移 `0051_operator_proxy_pools.sql` 建立池、成员和不可变密文修订。成员当前修订具有作用域内外键；数据库拒绝覆写或删除旧修订。
- 替换代理创建新修订；修改名称／状态只改变资源版本，不改变网络修订。成员与修订在同一事务提交，CAS 失败不能留下孤立修订。
- 使用现有加密信封，认证上下文绑定 operator、资源租户、池、成员、修订及用途。输入不实现 Debug，不保存无密钥凭据摘要，不返回原始异常。
- 运营路由不经过通用请求体哈希缓存。当前 POST 不提供持久幂等：网络中断、服务端错误或成功响应无法解析时，界面要求刷新核对结果，不自动重复创建。PATCH 使用版本控制。
- 凭据只保留在提交所需的组件内存，提交结束后清空；不写入 query cache、URL 或浏览器持久存储。切换用户／运营商重建表单与查询作用域。

## 后续接线

1. 将账号活动／待生效绑定与成员不可变修订关联；沿用单账号代理的兼容入口。
2. 在登录、发现、测量和发布前统一固定网络版本；历史查回／清理使用原执行引用，不读取当前配置来推断旧路由。
3. 通过执行器实际浏览器网络检查出口及重复出口；池地址数量不等于公网出口数量。
4. 账号切换路由须等待已持有浏览器结束，租约经过不等于资源已经释放。失败不静默直连，不以不断换 IP 重试平台拒绝。

验证结果与未完成事项分别记录在 `WORKLOG.md`、`TODO.md`，产品规格书保持不变。
