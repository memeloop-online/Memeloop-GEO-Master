# 推荐对象测量

## 产品目标

测量回答“用户在选购或选择服务时，AI 推荐谁、排在什么位置、为什么推荐、引用了哪些来源”。仅取得解释性回答和引用不能作为推荐测量验收完成。

任意问题仍可测量，不要求先上传企业资料。推荐对象包括具体产品／型号、餐馆、品牌和服务；不把资料页面或引用域名当成被推荐对象。

## 首个增量

- 使用现有后台 AI 提取调用，同时识别推荐对象，不额外向被测平台发送解析问题。
- 保存于同一分析版本的 `outcome.audit.recommendations`，随已有结果 JSON 持久化，不覆盖原始答案或旧分析。
- 区分答案中的出现顺序与明确表达的推荐排名。普通编号、并列推荐或“排名不分先后”不能自动转成推荐优先级。
- 名称、推荐依据与理由可定位到已保存答案；实体相关引用只使用本次已经核验的引用。AI 判断语义，代码仅检查结构、原文匹配和引用归属，不实现关键词或正则实体抽取。
- 页面在原始答案前显示推荐结果；旧版本缺少该分析不等于“没有推荐”，解析失败也不等于“没有提及”。
- 应用未发布，只支持当前抽取格式，删除旧格式重放。新增字段解析失败不丢掉可用答案和引用。

## 后续增量

0. 默认从问题集进入测量；问题集作为文件夹归纳多次记录，按同组测量生成排名变化报告。临时测量独立归组，提供单次推荐排名可视化。
1. 目标产品／餐馆及别名作为独立的测量配置保存，不默认拼入消费者问题，避免诱导提及。区分仅提及、明确推荐、否定及未出现。
2. 同口径问题、平台、观测面与时间范围内聚合推荐率、第一推荐位比例和排名分布，显示有效样本分母；未排序样本不计为末位。
3. 报告冻结分析版本及证据引用，支持推荐变化和竞品对比，不混淆网页推荐排名与传统搜索自然排名。

## 验收

- 一次真实选购问题 → 平台回答 → 自动存档 → 推荐表 → 原文／引用 → 刷新读回。
- 同样结构覆盖餐馆选择，不增加平台或品类专用解析器。
- 原文没有明确排名时不补造；没有推荐对象、旧版未分析、提取失败分别展示。
- 平台临时会话按既有生命周期清理，结果只依赖本系统存档查看。
- 测试使用通用虚构实体。实际账号、部署信息与原始运行记录不进入公开文档。

## 当前接口协作

- Rust 仅接受当前提取 prompt `geo.observation.extract.v4`、parser `geo.observation.extract.v6`，不保留旧格式重放。
- 执行器输出 `outcome.audit.recommendations`，结构为 `version: geo.recommendations.v1`、`status: verified|unverified` 与 `items`；条目包含 `name`、`kind`、`mention_order`、可空 `rank`／`reason`、`evidence_quote`、`citation_urls`。推荐字段不可用不能丢掉有效答案与引用。
- 执行器待修：推荐证据加入后超过审计总大小时，目前会整体拒绝有效答案。应单独处理推荐字段，不让辅助展示挤掉正文。
