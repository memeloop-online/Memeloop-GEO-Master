# 推荐对象测量

## 产品目标

测量回答“用户在选购或选择服务时，AI 推荐谁、排在什么位置、为什么推荐、引用了哪些来源”。仅取得解释性回答和引用不能作为推荐测量验收完成。

任意问题仍可测量，不要求先上传企业资料。推荐对象包括具体产品／型号、餐馆、品牌和服务；不把资料页面或引用域名当成被推荐对象。

## 首个增量

- 使用现有后台 AI 提取调用，同时识别推荐对象，不额外向被测平台发送解析问题。
- 保存于同一分析版本的 `outcome.audit.recommendations`，随已有结果 JSON 持久化，不覆盖原始答案或旧分析。
- 区分答案中的出现顺序与明确表达的推荐排名。普通编号、并列推荐或“排名不分先后”不能自动转成推荐优先级。
- 名称、推荐依据与理由可定位到已保存答案；实体相关引用只使用本次已经核验的引用。AI 判断语义，代码仅检查结构、原文匹配和引用归属，不实现关键词或正则实体抽取。
- 页面在原始答案前显示推荐结果；旧版本缺少该分析不等于“没有推荐”，解析失败也不等于“没有提及”。
- 应用未发布，只支持当前抽取格式，删除旧格式重放。新增字段解析失败不丢掉可用答案和引用。

## 后续增量

0. 默认从问题集进入测量；问题集作为文件夹归纳多次记录，按同组测量生成排名变化报告。临时测量独立归组，提供单次推荐排名可视化。
1. 目标产品／餐馆及别名作为独立的测量配置保存，不默认拼入消费者问题，避免诱导提及。区分仅提及、明确推荐、否定及未出现。
2. 同口径问题、平台、观测面与时间范围内聚合推荐率、第一推荐位比例和排名分布，显示有效样本分母；未排序样本不计为末位。
3. 报告冻结分析版本及证据引用，支持推荐变化和竞品对比，不混淆网页推荐排名与传统搜索自然排名。

## 验收

- 一次真实选购问题 → 平台回答 → 自动存档 → 推荐表 → 原文／引用 → 刷新读回。
- 同样结构覆盖餐馆选择，不增加平台或品类专用解析器。
- 原文没有明确排名时不补造；没有推荐对象、旧版未分析、提取失败分别展示。
- 平台临时会话按既有生命周期清理，结果只依赖本系统存档查看。
- 测试使用通用虚构实体。实际账号、部署信息与原始运行记录不进入公开文档。

## 当前接口协作

- 品牌归属候选已实现，通过本地定向验证、四组隔离 GET 夹具浏览器检查及两轮独立审查；最新完整前端运行仍有一项长文 PDF 超时，完整 CI、最终文案浏览器复验及部署后浏览器／供应商验收待完成，尚未合并或部署。唯一最新契约为提取 prompt `geo.observation.extract.v5`、parser `geo.observation.extract.v7`、推荐结果 `geo.recommendations.v2`；跨执行器、Rust 版本检查和 Web 读取同步更新，不保留旧格式重放或自动补字段兼容。
- 执行器输出 `outcome.audit.recommendations`，结构为 `version`、`status: verified|unverified` 与 `items`；条目保留 `name`、`kind`、`mention_order`、可空 `rank`／`reason`、`evidence_quote`、`citation_urls`，新增必填且可空的 `brand_attribution: {name, evidence_quote} | null`。仅产品可以非空；缺字段或伪造证据使推荐结果不可验证，不能静默补空。推荐字段不可用不能丢掉有效答案与引用，旧快照原件不改写。
- 当前执行器在推荐证据使审计超限时先降级推荐字段，保留答案、引用和有界来源；仅基础审计仍超限时拒绝。已有对应边界回归，不再列为未修复问题。

## 品牌归属与独立计数

- 归属由同次 AI 提取根据回答内明确证据判断，不新增推理或测量请求。归属名称使用回答原样品牌名，引文为包含完整产品名与品牌名的连续原文；名称前缀、外部常识、引用域名或模糊同现均不构成归属。证据不足返回 `null`，表示未知，不表示没有品牌。
- 直接品牌推荐继续按类型及名称／显式别名精确匹配，沿用原推荐率、排名和首位率。旗下产品另外分类，每品牌每份有效回答最多计一次；产品排名始终属于产品，不提升为品牌排名，也不将两类推荐相加。
- 有效回答数为 V；存在匹配归属的回答为正例 P。无匹配且存在未知产品归属记 U；所有产品均明确归属其他品牌、没有产品或验证空集合记明确非正例 N。已有匹配归属时，即使另有未知产品也只记 P；缺失或不可验证结果不计 V。
- 可判定数 K＝P＋N＝V－U，展示 P／K／U／V 原始计数，不新增归属推荐百分比，不把 U 当负例。结果、同条件趋势、跨平台对照及 CSV／PDF 共用口径，并保留逐产品归属原文、当前筛选与点击语言；不同问题、平台与条件不混算。

## 独立关注对象配置

- `ProjectSettings.measurement_targets` 保存 `{name, kind, aliases}[]`；默认空列表，项目 PATCH 整体替换，空列表清空。企业名称和产品资料不是隐式测量目标。
- 类型沿用产品、餐馆、品牌、服务及其他对象；名称与用户明确配置的别名去除首尾空白后精确匹配，不推断大小写、型号或品牌归属。同类型目标之间的名称交叉应明确报错，不能静默合并。
- 同目标同样本最多计一次推荐；别名命中排名不一致时单列，不取最好名次。原始名称、排名、分析版本和证据保留，不修改已存报告。
- 报告关注视图使用当前项目配置，不冒充生成报告时冻结的配置；完整历史仍保留原始名称。目标不自动加入消费者问题。
- 对话通过既有 `project_current`／`project_revise` 读写同一字段，无新 host op；API、Agent bundle 与 Web 须配套部署。
