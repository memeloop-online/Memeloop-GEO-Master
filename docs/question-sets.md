# 问题集、冻结评估与测量绑定实施契约

细化冻结规格第 7.3、11.7 和 12.4 节，不修改产品计划。本契约尚在实施，不能视为真实测量或下一轮优化已经完成。

## 交付路径

在 P13 管理有版本的问题集，P12 从确切版本选择问题和测量协议，服务端解析并冻结问题文本、身份和用途；P00 通过同一业务接口创建、修订及安排测量。旧临时问题保留，但明确未分类，不能成为优化输入。

问题身份、问题修订、问题集和问题集版本分别建模，所有引用限定在同一运营商、租户和项目。修订保留旧版本，旧计划和旧报告不改写。问题至少保存意图、产品引用、市场、语言、来源及业务权重；未知产品或资料引用不能伪造成有效知识。

## 自动划分规则

冻结评估用途由服务端分配，页面没有手工切换评估/优化的开关。

- 项目内跨问题集维护追加式问题身份登记；同一标准化问题不重复计数。
- 标准化版本固定为 Unicode NFKC、小写和首尾/连续空白归一，不移除标点，不宣称语义改写检测。
- 新一批登记前已有 N 个不同身份，本批新增 M 个；分配 `ceil((N+M)/5)-ceil(N/5)` 个新的评估身份。使用项目持久随机种子和标准化文本摘要确定排序，输入行顺序不改变结果。
- 一个问题时为一个评估问题；累计 2–5 个时仍为一个，6–10 个时为两个。界面显示实际数量，没有优化问题时明确说明。
- 身份的用途永久固定。编辑保留身份和用途，所有历史标准化文本作为该身份别名保留；与另一身份冲突时拒绝合并。
- 删除、重新加入、复制到另一个集或换周期不重置用途。任意版本删除部分问题后，其实际比例可能不等于 20%；不得通过重新分配已曝光问题来伪造精确比例。
- 这里保证登记集合按取整规则分配及身份不翻转，不保证人工从未见过问题，也不以模型推测语义相似性。

并发登记、别名唯一性、版本发布和请求幂等在同一项目事务内完成；内存实现提供等价原子边界。修订要求当前基版本，旧基版本冲突时保留用户草稿。

## 测量与旧数据

现有临时 `measurements` 保留；新增默认空的 `bound_measurements` 只接受问题引用及账号/协议/时间，不接受覆盖问题文本或用途。两类合计沿用既有批次限制。

测量输入新增可选绑定，包含问题集、集版本、问题身份、问题修订、用途及划分策略版本；文本、市场和语言来自不可变问题修订。无绑定的旧数据永远是未分类，不能因其自由文本版本标签碰巧等于真实 ID 就升级。

缺省绑定反序列化为 None，序列化时省略，保持旧请求摘要、目标 ID 和比较键。新绑定参与新目标身份与摘要。旧 runner 证据协议无需由外部执行者声明用途，权威用途只能来自服务端冻结输入。

报告按优化、冻结评估、旧未分类分别保留比较口径和计划分母；旧报告缺少分类时明确显示未知，不回填历史。

## 优化输入边界

新增独立 typed 投影，而非把完整周报、测量详情或自由文本摘要交给生成模型。只允许合法绑定为优化用途、有效且非模拟的观测进入投影；冻结评估和未分类的题目、答案、引用、状态派生结论及混合汇总均不进入。

当前投影只包含可核验的优化问题/修订/目标/观测引用及协议，不返回问题正文、答案或行动建议；后续消费者仍需通过作用域校验读取所需资料。不从缺测推断未提及，不伪造事实诊断。当前生成器没有读取测量答案；此投影是后续优化器的受控入口，不冒充已实现 NextCycleAction 或完整优化器。

P00 问题发现返回版本、用途计数和可调度引用；自动优化发现不返回评估文本。显式人类报告仍可查看评估详情，不把任意人类复制文本的全局防泄漏当作此功能的保证。

## 页面与接口

- P13：创建、按行批量输入、版本历史、编辑/增删形成新版本、只读用途与数量、元数据、冲突保留；覆盖空态、加载、失败、只读、窄屏。
- P12：绑定模式选择真实问题集版本和问题；临时模式明确“未分类，不进入优化”；保留真实渠道未验证提示。
- API：问题集列表/创建、版本列表/详情/创建，作用域由登录身份决定，编辑须写权限。
- P00：typed 创建/修订/发现工具，绑定测量复用同一计划服务，不允许覆盖身份或用途；宿主契约与生成 bundle 同步升级。

## 验收

必须覆盖：去重与顺序无关、取整、并发登记、别名冲突、编辑/移除/重加用途不变；版本不可变与幂等冲突；跨租户/项目/版本成员伪造拒绝；旧 JSON 和身份黄金回归；报告分类分离且缺测分母完整；优化投影的评估内容金丝雀排除；P00 真实引用接线；页面创建→修订→选择版本→冻结测量；显式 PostgreSQL 和原生运行时回归。真实外部采样单独验收。
