# P00 内容媒体工具实施契约

状态：实施中，未验收。冻结产品规格不变；本文落实对话上传图片、选择已有媒体、读取内容并插图的已有要求，不替代一般正文编辑、缩略图或外部发布。

本地实现和定向实库/原生循环已通过；提交后 CI 与真实模型到详情页读回仍待验收，详见工作日志。旧正文不符合 schema 2 约束时明确失败并保持原文，不截断后迁移。

## 同一业务路径

HTTP 与 AI 复用 `content_media::bind_image` / `binding_page`，保留真实静态图片解码与项目绑定。AI 不能提交对象地址、下载字节、账号凭据或作用域。已有图片从项目媒体列表选取；新绑定只能来自 Rust 绑定到当前回合的附件，并核对对象、版本、摘要、大小、声明类型及文件名。

## 版本定点读取

`ContentRepository::get_revision` 按项目、资产和版本读取单条正文；内容检查/修复的基础版本、文本及 ZIP 导出也使用同一入口。`find_exact_child_revision` 只查询同资产、同基础或派生版本的直接子版本，按修订号每页读取 64 项，解码后比较完整结构化正文。页大小不限制总历史搜索范围，不用标题、块 ID 或原始 JSON 字符串相等替代语义比较；旧 JSON 省略的默认字段保持兼容。

PostgreSQL 的执行、条目及资产读取只向应用返回对应元数据投影；迁移 `0035` 为直接基础和派生关系增加索引。完整历史列表及修改正文的聚合事务保持原路径，数据库内部仍可能读取聚合存储；这不是完整历史分页或整体吞吐验收。定向回归覆盖无关损坏历史不影响选定版本、跨页精确子版本、旧字段兼容、检查结果投影及作用域隔离。

## 工具接口

新增 `geo.hostops.v15` 四项工具：

| 模型工具 | 宿主操作 | 请求 |
|---|---|---|
| `content_media_list` | `content.media.list.v1` | `after?`, `limit?`（默认 10，最多 25） |
| `content_media_bind` | `content.media.bind.v1` | `attachment_id` |
| `content_document_read` | `content.document.read.v1` | `execution_id`, `item_id`, `revision_id?` |
| `content_media_insert` | `content.media.insert.v1` | `execution_id`, `item_id`, `base_revision_id`, `binding_id`, `after_block_id?`, `alt`, `caption` |

媒体投影仅返回绑定 ID、对象完整键、真实类型、字节数和尺寸；列表有 `next_cursor`。正文读取默认读取该条目当前版本；指定历史版本必须属于该条目实际资产。返回执行、条目、资产、版本、当前版本、是否复用及结构化正文，不额外返回原始附件或全部证据。正文过大时明确失败，不截断后供模型覆写。

## 插入与重试

- 插入到指定顶层块之后，省略位置则追加。位置不存在、基础版本过期或绑定已撤销均明确失败。替代文本/说明沿用媒体节点的长度边界；不接受任意富文本或证据身份。
- 服务端从基础版本重建文档，只新增独立媒体块，其余正文、块 ID、引用、历史版本和来源证据不变。新块无伪造事实引用；结构升级为 schema 2，由正常检查读取替代文本与说明。
- 新块 ID 从作用域与完整请求确定性推导。同一基础版本、相同请求重放时，通过精确子版本文档匹配返回原收据，不再新增版本；比较基础或派生版本及完整文档，不仅凭块 ID 认定成功。并发冲突后重新查回，不能改用最新基础版本盲插。
- 普通条目调用 `ContentService::edit`；跨周期复用条目调用 `fork_reused_item`，不能修改来源资产。重放可读取已生成目的资产的精确派生版本。
- 仓储继续在写入 guard/事务内复核媒体用途与基础版本。此前读到可用绑定不是提交授权。新版本是待检查草稿，不表示检查、发布或 AI 效果测量成功。
- 宿主账本记录作用域、参数摘要、调用与结果；不将现有回合序列号账本描述成完整跨进程恢复。返回可导航的执行/条目/资产/基础与新增版本、块 ID 收据。
