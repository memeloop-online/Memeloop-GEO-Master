# 未知发布结果的自动查回

实施设计与增量记录。细化冻结规格中的“发送后崩溃不盲目重发”，不代表真实渠道已验收。

## 已落盘的基础切片

- 浏览器发送后跳转到固定公开资产路径、但读回失败时，保存 `publication_candidate` 未验证线索；仍为 `unknown`，不设置 `public_url`。Rust 校验原执行来源、冻结标题/正文摘要、时间及固定 URL 路径，删除不可信/歧义线索，再绑定原尝试、目标、账号及连接器版本。候选不能提升发布成功或格式能力。
- 迁移 `0023` 与独立 `PublicationLookupRepository` 保存查回任务、单次领取执行 ID 和追加观察。输入从原作用域下的发送尝试读取，不接收调用方提交的 URL；只允许 `unknown` / `asset_observed` 观察，不修改原发送尝试。领取过期只允许新的只读执行 ID；追加结果与后续排期同事务保存。数据库时钟拒绝过期写入，历史表禁止更新/删除并约束执行与原尝试一致。首次无回执入队后，允许从同一原尝试的晚到未知回执一次性补入线索并恢复排期，不覆盖已有线索。
- 已装配 PostgreSQL 后台扫描器：每 30 秒分页发现至少五分钟前的未知/无回执发送，入队后等待原子领取完成再启动只读任务；暂停项目仍查回，不重发。缺少 browser runner 时不启动。
- 迁移 `0024` 在发送前保存不可变加密执行绑定，包含原账号归属、平台身份、连接器版本及实际出口。查回可使用同身份更新后的 session，但不换账号、归属、出口或连接器版本；历史无绑定尝试仍为未知。绑定不进入公共 API 或观察证据。
- 执行服务仅调用 `lookup`，验证执行 ID、真实 runner 来源、版本、时间、精确候选 URL、账号归属与冻结正文。结果只追加 `asset_observed` 或 `unknown`；观察时间与接收时间分开保存。账号预检租约在确认关闭浏览器后释放，启动/清理结果未知时等待有界租约到期。
- 观察到资产后六小时复查，无候选十五分钟，其余错误指数退避至最多一小时。这些排期不限制整体并发，也不增加人工操作。观察读取 API、P12 与 P00 摘要已接线，验证状态见工作日志。无候选资产发现、跨周期原目标导航、发送因果证明、报告投影和真实渠道验收仍需完成；新增 PostgreSQL 套件必须显式执行，默认 ignored 不算通过。

## 只读界面与 Agent 契约

`GET /api/v1/projects/{project_id}/channel-targets/{target_id}/publication-lookup`
沿用当前登录会话及项目授权。兼容前端统一的 `tenant_id`、`project_id` 选择参数，但不从查询参数扩大作用域。

- 响应包含 `target_id`、`attempt_id`、可空 `job`、`observations` 和 `next_before`。未安排查回或没有发送尝试时返回空记录，不因 GET 入队或启动浏览器。
- `job` 仅返回查询次数、下次查询时间、稳定错误类别和当前是否持有有效执行租约。观察仅包含执行 ID、发现类型、观察/接收时间、错误类别及经校验的公开资产链接。原始 evidence、正文、登录态、账号平台身份、出口与租约凭据不返回。
- 新记录在前，每页最多 20 条；`before` 为同作用域、同原发送下的一条观察执行 ID，按 `(received_at, execution_id)` 继续向前读取。仓储仅取一页加一条，拒绝不存在及跨作用域游标，不加载完整历史。新增观察不覆盖旧记录。
- P12 原资料发布卡片及本轮正文分发目标可读取查回、刷新和加载更早记录；空态、初次/分页/刷新错误均独立显示，刷新失败保留已有观察。链接不携带凭据，只允许当前适配器固定公开资产路径。
- P00 既有渠道清单工具增加可选 `publication_lookup` 摘要，只有结果未知且已有尝试的发布才读取；摘要不携带公开 URL 或原始证据，原执行状态保持未知。新增字段兼容既有响应，不新增用户确认或重发操作。
- 跨周期 `reused_unknown` 行尚未暴露原 `channel_target_id`，不能把本轮覆盖目标冒充原发送目标。生成正文的 P00 分发工具仍需专用查回引用；既有来源渠道清单不冒充完整正文分发清单。

## 当前缺口

`channel_execution_attempts` 为目标保留唯一发送尝试；`finish` 只保存一次结果。首次结果为未知后，不能通过覆盖该结果来补写成功。新查回扫描与首次发送、能力投影独立：观察到同正文资产不证明原发送成功，也不升级连接器能力。

浏览器已有只读 `lookup` 操作，但支持范围取决于具体适配器。当前查回需要冻结标题、正文和候选公开 URL；发送超时不一定取得 URL。未验证线索与已验证的 `public_url` 分开保存，支持同一原尝试的晚到候选一次性补入；完全没有候选时仍不会搜索资产列表。

## 实施顺序

1. 保存候选资产线索：把发送后观察到的 URL、提供方资产标识和事件关联作为**未验证线索**独立保存，不计成功、不赋予连接器发布能力。URL 必须符合适配器固定公开路径，不能携带账号令牌或任意跳转地址。
2. 建立独立查回账本：关联原 `attempt_id`、冻结版本/变体、账号、连接器版本，保存下一次查询时间、领取 token/到期时间、查询次数与稳定错误码；每次查询使用独立执行 ID，结果追加保存。过期租约只能重新查，不能重新发送。
3. 分页发现未知/缺少回执的发布尝试，原子领取查回任务，通过账号服务恢复加密 session 并重验身份，以同一指定出口调用只读 `lookup`。项目暂停停止新发布，不停止已发生副作用的只读查回。账号不可用则退避，绝不换账号认领资产。
4. 无候选 URL 时，仅使用已有、经验证的账号自有资产列表发现候选。核对冻结正文、标题和账号；多个相同候选、分页截断、访问失败或缺少发送关联均保留未知。列表中没找到不等于未发布，不能据此释放预算或重发。
5. 将可信查回结果投影为追加证据，独立记录观察时间和接收时间；在一个事务中幂等更新意图/命令的当前已知状态。原发送尝试、原未知证据和历史报告不修改。
6. 扩展正式及旧渠道报告输入，按原截止区分当时未知和后来验证。已保存周报保持不可变；现有显式更正可纳入迟到证据，自动更正排期需另行实现。

## 证据不能混用

- 存在一篇同账号、同正文的旧文章，仅证明资产存在，不证明本连接器成功执行了原发送。
- 升级发送结果或发布格式能力，需要真实发送与该资产的关联证据；缺少发送事件/提交后资产 ID/可信时间关联时，不制造一条 `Published` 回执。
- `project_saved_publication_verification` 当前仅接受原尝试的可信发布结果。新查回路径应有独立投影入口并核验发送关联，不能把原 `Unknown` 改成 `Verified` 来复用它。
- runner 实测来源标记、执行 ID、版本、账号归属、冻结内容摘要、时间窗口和引用资产必须相符；夹具、旧版无来源标记及适配器自报都不能升级。
- 公开读回使用无账号 Cookie 的浏览器上下文，同时保持指定出口；不允许代理失败后直连。

## 验证入口

分别覆盖发送前后崩溃、已取得 URL 但读回失败、完全无 URL、重复/延迟查询、进程重启、多副本领取、跨租户/账号、被暂停项目、重复正文歧义、不可访问资产、伪来源/版本/摘要、截止前未知与截止后更正。

最终端到端必须证明：原发送只发生一次；查回没有发布操作；结果晚到不覆写原报告；无法证明时仍显示未知。单独的浏览器查询夹具不能替代这些验收。
