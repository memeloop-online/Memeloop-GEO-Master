# Agent 工具调用账本

本文件细化冻结规格的 W00 实际调用记录。实现与验证状态见 `WORKLOG.md`；账本接通不等于已完成 running 回合租约、checkpoint 重入或自动恢复。

## 权威边界

- `TurnInput.run_id`、项目作用域和仓储由 Rust 应用装配提供。脚本消息、模型 tool ID、返回元数据都不能指定账本所属运行或宣称工具已经执行。
- 每个 Agent bridge 使用 Rust 序号分配调用 ID，绑定 run、版本化 host op 和实际通过 DTO 校验的请求摘要。同一个 ID 的工具名、参数或幂等摘要变化必须冲突。
- 账本只保存摘要、状态、权限/预算结果和固定的 Rust 语义标签。不保存提示词、正文、账号登录态、模型密钥、原始供应方错误，不伪造结果对象引用、费用或零成本。
- 生产及内存开发应用装配均为 Agent 运行注入仓储记录器。独立引擎探针和已有内容工作流不伪造 Agent Run；内容执行继续使用自己的持久业务账本，不借此声称已有 Agent 中途恢复。

## 生命周期

1. `Intent`：作用域内的运行必须正在执行，保存调用身份及摘要。已有相同记录只返回原记录，不覆盖内容。
2. `Attempted`：只有允许执行的 Intent、仍在执行的运行可以原子领取；只有一个调用方取得执行权。先持久化领取，再调用能力。
3. `Succeeded / Failed / Unknown`：真实能力结果经过 DTO 与关联校验后才能保存结果。相同终态重放保持幂等，不同终态冲突；没有将 Unknown 重置为可执行的入口。

`Succeeded` 表示 host op 返回了符合契约的结果，不表示其内部所有发布分支成功。外部结果未知、在途取消/超时、发送后结果不能验证时保留不确定性；发布是否成功仍由发布业务账本和回执证明。

这里的 permission/budget 是宿主调用层判定，不替代业务服务的来源、账号、费用预留及发送前检查；业务检查失败也必须保留原业务结果。参数校验、调用次数预算或取消在创建 Intent 前拒绝的请求，不会产生实际调用记录。

前置账本写入失败不得调用能力。能力已调用后终态写入失败不得返回虚假成功；持久 Attempted 需要后续核对，不能换调用 ID 再做一次。运行取消或结束不妨碍已开始调用补存真实结果。

## 执行与取消

- V8 隔离体继续使用独立 current-thread Tokio runtime；仓储、模型和业务能力在应用 runtime 上执行，不将连接池迁移进隔离体。
- 记录器包围实际能力调用及返回校验；不能在发布回执、测量样本、内容分支关联校验之前记录成功。
- 调用的应用侧任务负责收尾。隔离体停止等待，不等于已经撤销外部副作用；收尾写入具有独立、有界时间，不受已过期的执行截止时间立即取消。
- 不新增全局并发门槛、人工确认或账号审批。沿用既有业务幂等与调用预算。

## 尚未由此解决

- 运行中回合的跨副本租约和 fencing。
- MemeLoop 脚本重入、稳定分支选择与中途 checkpoint。
- 已尝试但缺少终态的工具按具体业务账本核对，以及可证明安全的恢复。
- 可重放的结果引用及稳定重入位置。当前 Rust 序号只标识本次运行中的调用，不是跨重启的工作流步骤键；遇到已领取身份时停止，不直接复用输出或重新执行。
- 真实模型费用结算及完整商业账务。

既有 `append_tool_call` 保留兼容存储用途；生产调用改用显式 begin/attempt/finish 生命周期。完成结果 checkpoint 与实际调用账本分别保存，不能从 JavaScript 自报的“已完成工具列表”生成记录。

## 后续恢复实施接缝

对当前锁定的 MemeLoop 0.3.3 检查结果：`createAgentToolLoopRunner` 每次创建新状态并开始 turn，没有直接接受已恢复阶段的入口。`AgentLoopRuntime` / `LoopScriptCheckpointStore` 的 checkpoint、CAS 和 fencing 能力不等于直接 runner 已消费恢复状态。当前进行中 canonical 消息仍在内存；`rust:N` 的编号受并行回调到达顺序影响，不能直接用作跨进程重放键。

后续应按依赖顺序实施，不在 GEO 复制模型循环：

1. Rust 保存有租约及 fencing 的 Run 执行权，同时冻结输入、bundle/profile 摘要、模型路由与预算信封；租约丢失后旧执行者不得推进 run/checkpoint 或开始新调用。
2. 建立私有、有大小边界的宿主结果存储，校验后的结果与终态引用原子落盘。已开始的调用允许按原 attempt 身份补存晚到结果，但不得借此取得新的执行权。
3. 上游提供最小的阶段恢复适配接口；工具身份绑定模型迭代、已持久化的工具决策与索引，而非到达顺序。先保存模型决策，再派发其工具；恢复消息必须保持 canonical 顺序和输入版本。
4. 对缺少可靠终态的 Attempted/Unknown，读取对应业务账本核对。只有证明不会重复副作用的步骤才继续，不能用重跑模型或换调用编号替代恢复。

上游修改及提交 PR 仍待产品负责人单独授权；当前未修改上游。上述为实施接缝，不是已交付能力。恢复验收须覆盖工具前、工具返回后但 checkpoint 前、失租/取消、并行工具乱序、进程重启和晚到结果。

## 验证要求

内存及 PostgreSQL 覆盖作用域、身份冲突、并发领取、取消前后边界、终态幂等及 Unknown 不重试。Worker 覆盖真实调用顺序、前置写失败不执行、返回校验先于成功、超时/取消/异常和无原始秘密记录。应用测试必须先受理并领取真实仓储 Run，再通过原生 bundle 执行工具；只直接调用记录器不算整条路径验收。
