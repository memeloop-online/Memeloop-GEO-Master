# 远程登录组件替换

状态：实施设计，尚未交付。替换通用远程桌面交互，不重写账号、身份核验、加密会话和发布/测量流程。

## 组件与运行环境

拟采用 noVNC 客户端、websockify WebSocket/RFB 转发和 TigerVNC/Xvnc 虚拟显示，运行有头 Playwright Chromium。接入前固定版本、核验维护状态及许可证分发义务；不能把依赖选型写成已完成安装。noVNC 本身不是浏览器服务，不能显示现有共享 headless Chromium。

交互登录与自动执行分开：交互登录使用独立浏览器进程和独立显示器，生产优先每会话独立容器或 pod；后台自动测量/发布仍复用现有 headless 执行链路。远程桌面必须操作后续身份核验、`storageState` 保存所使用的同一浏览器上下文，不复制到另一套不受管理的浏览器。

Windows 原生应用和数据库可保持运行，但此登录 runtime 需要 Linux 容器、WSL2/虚拟机或远程 Linux runner。不能仅安装 npm 客户端就宣称 Windows 本地远程桌面可用，也不能共享宿主主桌面。

## 接缝与实施顺序

1. `packages/browser-runner` 增加独立交互会话 runtime，继续应用原账号代理、身份识别、完成/关闭和会话保存。先以隔离 Linux 环境验证真实显示、登录及浏览器上下文一致性。
2. Rust 账号 API 增加同源 WebSocket 连接入口和短期会话绑定授权；校验登录、Origin、租户/运营商及会话归属。目标由服务端确定，不接受客户端 VNC 地址。runner 密钥、代理秘密及 Cookie 不下发客户端。
3. React 两种账号入口共用 noVNC 包装组件；替换截图轮询、坐标表单、按键枚举及自制点击映射。完成、取消、失效、撤权立即断开远程输入并回收资源。
4. 新旧运行方式分别显示真实能力；仅在新 runtime 通过验收后退役截图/action 接口，不能以失败时静默切回自制协议掩盖未完成。

RFB 绕过现有逐动作登录控制守卫，必须重新验证会话输入生命周期、完成后断开及服务端隔离。前端按钮变灰不等于服务端撤权；页面事件守卫不能冒充无竞态的隔离机制。采用非 root、隔离文件系统及受限网络，不开放浏览器调试入口或宿主文件。

## 使用体验

- 普通文本正常显示，不额外掩码；凭据字段沿用被登录平台自己的行为。
- 使用成熟输入法、剪贴板和远程桌面能力；不新增自制文本注入通道。
- 安装并验证中文字体与远端输入法。必须实际测试中文组合输入、选字、退格和 Unicode/emoji 粘贴；noVNC 名称不能作为 IME 支持证据。
- 客户端缩放与服务端分辨率协商分开验收。断线重新授权后恢复同一未过期会话，而非悄悄创建空浏览器。
- 不增加账号用途声明、逐篇确认或人工审批。

## 交付验证

必须分别验证 Linux 无物理显示环境、生产 ingress WebSocket 和 Windows 客户端：

- 中文输入、剪贴板、滚动、触屏、窄屏、分辨率与焦点；
- 断线恢复，取消/过期/失权清理，身份保存后既有连接不可继续输入；
- 两租户并行隔离，跨站连接和过期凭据拒绝，客户端不能指定任意远程目标；
- 登录与后台执行出口一致，指定代理失败不直连；
- 实际登录→身份核验→加密保存→进程重启→模型发现→提问→答案与引用证据。

自动夹具和真实平台验收分别记录；真实身份、登录截图、凭据和运行地址不进入公开仓库。若本地 IME 等必需体验无法通过，再评估完整 KasmVNC 客户端/服务端方案，而非继续增加自制遥控功能。
