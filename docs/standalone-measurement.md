# 独立话题测量

用户可以测量任何自行输入的话题。企业资料只作为关键词、问题与话题推荐的可选输入；测量不以品牌信息、知识入库、内容生成或优化周期启动为前置条件。项目仍提供会话、账号与数据隔离边界，空白草稿即可使用。

## 运行契约

- `StandaloneMeasurementPlan` 独立保存标题、冻结问题与测量协议、计划分母及执行目标。没有 `cycle_id`，不创建伪造优化周期。
- 新入口为项目作用域下的 `POST/GET /measurement-plans` 和 `GET /measurement-plans/{plan_id}`。创建幂等，问题集引用可选，直接输入的问题不自动加入优化输入。
- 复用账号双来源、加密会话、出口策略、目标领取、尝试记录、后台扫描和测量证据校验。登录成功不是测量成功。
- 发布清单及历史周期的序列化、目标 ID 和报告口径不变；独立测量不得自动混入已有周期报告。
- 用户只需选择已连接账号并输入问题。协议标识由界面提供；模型必须对应实际网页请求，不伪造自动识别，不将普通聊天冒充联网搜索。
- 结果保留实际回答、引用与运行状态。拒答、搜索证据不足、登录失效和技术缺测分别呈现；不把缺测计成未提及。

## 实施与验证边界

迁移 `0030` 为既有渠道目标增加第三种独立测量归属，严格保留三类所有者的互斥关系。计划和目标原子写入，跨项目隔离、并发幂等和重启读回须实库验证。

当前代码和测试仍在整合；不能根据此契约或登录页已打开宣称真实搜索已验收。正常用户测量不需要填写企业启动表单；仅有原始账号连接时不自动发送测试问题。实际联网测试单独记录脱敏结论，不提交真实账号、登录截图或私有运行信息。
