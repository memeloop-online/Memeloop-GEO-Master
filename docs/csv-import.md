# CSV 知识导入

本实现细化现有知识库需求，不改变产品规格。验证状态以工作日志为准。

- 新解析结果标记 `deterministic-csv-v2`；已有 v1 版本与发布快照保持不变，混合版本知识发布保留各自解析器记录。
- 输入为 UTF-8、逗号分隔的 `text/csv`，允许文件开头的 UTF-8 BOM。
- 第一条逻辑记录是表头，后续每条记录形成独立表格片段。引号中的换行不增加逻辑记录编号；引号外完全为空的物理行忽略，含空格的单元格不被裁剪。
- 片段采用 `{"headers":[...],"values":[...]}`，保留列顺序、重复或空表头、空值、前导零、空格、单位与币种原文。所有单元格均为字符串，不求值公式，不推断数值类型。
- CSV 引用保存从 1 开始的逻辑记录及列区间，另记表头记录 1。界面明确区别于物理文本行号。
- 原文件 SHA-256 包含原始 BOM 和换行；解析时去除 BOM 不改变版本摘要。片段另有自身文本摘要。
- 不完整引号、非法引号位置、列宽不一致、无数据行和非法 UTF-8 都拒绝解析，不创建部分成功的资料版本或知识发布快照。
- 为限制解析资源放大，首版支持最多 256 列、10,000 条数据记录、单元格原编码至多 256 KiB、完整记录文本至多 32 MiB。补充的生成证据片段另有累计 32 MiB 上限，逐片记账；两类文本合计至多 64 MiB。超出后明确解析失败，不以截断或静默省略片段宣称成功。原始文件保留，大表后续通过异步分批解析扩展。

普通文件上传完成时导入；P00 附件上传仍只保存对象，需在对话中调用导入工具才进入知识库。两条路径使用同一解析器，沿用项目作用域、摘要核验、用途和幂等规则。

CSV 被浏览器声明成旧版电子表格 MIME 时，前端按 `.csv` 扩展名声明为 `text/csv`，服务端仍严格检查内容。这不意味着支持二进制 Excel 文件。

本批不实现 XLSX、PDF、DOCX、OCR、结构化事实提取、自动产品识别或向量检索；CSV 成功入库不等于这些能力已具备。

## 自动生成的证据范围

内容生成每次最多选用 24 个片段，每个引用最多 1,600 Unicode 字符。新导入的超长记录始终保存完整原记录，同时生成独立持久证据片段：

- 可完整容纳的相邻单元格按列区间分组，保留原表头和值。
- 单个超长单元格按完整 Unicode 标量边界分片；定位保留原逻辑记录、单列及单元格内从零开始、不含结束位置的 `start_char` / `end_char`。
- 过长表头独立定位在记录 1，不截断或重复塞进每个值片段；值片段仍绑定同列和表头记录。每片有自身 chunk ID、摘要与完整 JSON，不冒充整个原记录。
- 生成按来源内片段序号选用可容纳证据，不能直接截断超长 JSON；引用校验使用真实已保存片段和定位。
- 普通知识检索仍只返回完整记录，避免同一行与多个生成分片重复召回。资料详情区分完整记录与生成证据片段。

没有可用证据时仍阻断相关生成，不凭空生成。单次证据包不保证覆盖整张表；宽表和长单元格不再仅因整行超过引用长度而完全退出生成。

旧资料版本不会被就地改写或伪造新片段；既有版本的分片补建和重解析迁移尚未实现，不能假设幂等重放旧导入就会新增分片。此项不是 XLSX 或任意大表异步解析实现；具体本地、数据库及界面验证状态见工作日志。
