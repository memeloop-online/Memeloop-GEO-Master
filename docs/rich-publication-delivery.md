# 富文本与图片发布实施契约

状态：正在实施，未完成真实渠道验收。本文细化既有产品规格，不修改冻结计划。
编辑与媒体规则沿用 `rich-content-contract.md`、`content-media-contract.md`；
发布、查回及报告仍使用已有意图、outbox、尝试和证据账本。

## 冻结载荷

普通文本历史载荷、序列化、摘要、变体及意图身份保持不变。
富文本使用独立版本化载荷，绑定正文 revision、格式、转换策略、结构树和按正文
出现顺序排列的媒体清单。媒体清单包含精确用途绑定、对象版本、字节摘要、实际
类型、长度、尺寸、替代文字、说明和用途；重复图片仅在传输字节时去重。

正文结构、图片顺序或媒体身份变化必须改变富文本载荷身份。
数据库物化、outbox、发送前检查、执行器及查回复用同一载荷，不在某一层降为
纯文本。平台不支持的节点或媒体明确返回能力缺口，不自动删除内容再发送。
外部地址不能替代租户内媒体对象；凭据、图片字节和临时下载地址不进入持久载荷。

## 发送授权与撤销

已授权下载快照不等于允许公开发送。媒体传输到受控执行器后仍须复核用途。
发送授权沿用现有发送尝试，以单向、一次性的持久状态转换实现，不另建发布任务。
这不是用户审批步骤。

授权事务与媒体撤销共享项目、既有发送资源、排序后的对象和用途绑定锁：

- 撤销先提交：授权失败，不向外部平台上传或提交内容。
- 授权先提交：仅绑定到该尝试、账号、会话和载荷的一次执行获得发送权。
  此后撤销不能保证停止已获授权的外部动作。
- 只有实际完成首次授权转换的请求获得可执行许可；并发请求或重启后的重复请求
  不获得新的许可。授权响应丢失时保留未知，不以重试制造第二次上传或发布。

线性化点是授权事务提交，不是浏览器物理点击。若不在外部网络等待期间持锁，
无法保证提交授权之后、浏览器动作之前发生的撤销仍能阻止该动作。
事务不跨媒体传输、浏览器等待或平台请求持有数据库连接。

授权必须早于首次向外部平台传输正文或图片；编辑器自动保存和自动上传也属于
外部动作，不能仅在最终“发布”按钮前检查。过期或已结束尝试不能重新获得许可。
授权成功本身不产生已发布、公开验证或格式能力证明。

## 执行器传输

使用单独的、服务端认证的有界媒体传输，不扩大现有通用 JSON 请求范围。
维护中的 multipart 实现或等效的受限二进制传输负责接收字节；执行器验证精确
清单成员、摘要、长度和总量后才能请求发送授权。
只接受原始图片字节，不接受任意路径、远程 URL 或持久客户端凭据。
临时内容仅存受控执行环境，清理覆盖成功、失败、取消、过期及进程恢复。

发送回调地址与身份来自部署配置和原执行绑定，不由模型或正文指定。
一次性授权在 API/数据库端消费，不能只依赖执行器进程内去重。

## 公开验证

富文本公开读回须验证作者、全文以及该格式支持的结构、图片顺序和对应关系；
匿名上下文不携带账号 Cookie，并沿用被冻结的网络策略。
平台合理变换通过版本化规则比较，不能把图片 CDN URL 相同当作图片内容证明。
既有仅标题/纯文本读回不能升级富文本为 verified，也不能产生富文本能力记录。
暂未实现对应查回的渠道保持 unsupported 或 unknown，不改变历史原尝试。

## 工作分工与验收

1. 领域：版本化载荷、结构和媒体身份、旧格式黄金字节回归。
2. 持久化：事务内媒体核验、正式及单篇物化、原 outbox 贯通与重启重放。
3. API：精确能力、载荷关联、发送授权回调及禁止纯文本证明升级富文本。
4. 执行器：有界媒体接收、一次性授权、真实编辑器上传/提交、匿名结构与图片读回。
5. 联合验收：原生 AI 生成/插图 → 同版本详情 → 发布 → 公开读回 → 报告；
   包含撤销先后竞争、授权响应丢失、进程重启、账号变化和未知不重发。

单元、隔离数据库、浏览器夹具、CI 和真实平台结果分别记录。
上述工作包中任一通过，均不代表完整富文本发布已经交付。
